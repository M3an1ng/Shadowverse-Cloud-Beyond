# 进化点击错误修复总结

## 问题描述

用户报告进化解锁后点击进化按钮显示错误信息：**"本回合已使用过进化点或无法进化"**

## 根本原因分析

通过深入调查发现了以下关键问题：

### 1. 前端属性名不一致
- **问题**：前端 `evolveCard` 函数检查 `playerState.canEvolveThisTurn`
- **实际**：前端状态管理使用的是 `playerState.canEvolve`
- **影响**：导致前端验证失败，显示错误信息

### 2. 后端状态同步缺失
- **问题**：后端进化后设置 `CanEvolve = false`，但没有立即通知前端
- **影响**：前端状态与后端不同步，可能导致UI显示错误

### 3. 前端状态计算逻辑
- **问题**：前端EP更新时重新计算 `canEvolve`，可能覆盖后端的正确状态
- **影响**：可能导致状态不一致

## 修复方案

### 修复1：前端属性名统一

**文件**：`src/gameManager.js`
**位置**：第731-739行（`evolveCard` 函数）

**修改前**：
```javascript
if (!playerState.canEvolveThisTurn) {
    // Check local flag
    console.warn(
        "GM: EvolveCard rejected - Local state indicates evolution already used or unavailable."
    );
    alert("本回合已使用过进化点或无法进化。");
    return;
}
```

**修改后**：
```javascript
// FIXED: Use correct property name 'canEvolve' instead of 'canEvolveThisTurn'
if (!playerState.canEvolve) {
    // Check local flag
    console.warn(
        "GM: EvolveCard rejected - Local state indicates evolution already used or unavailable."
    );
    console.log(`%c[EVOLVE_CLICK_DEBUG] playerState.canEvolve: ${playerState.canEvolve}, playerState.ep: ${playerState.ep}, playerState.maxEP: ${playerState.maxEP}`, 'color: red; font-weight: bold;');
    alert("本回合已使用过进化点或无法进化。");
    return;
}
```

### 修复2：后端状态同步增强

**文件**：`Server/Services/GameService.cs`
**位置**：第1635-1647行（`EvolveAsync` 方法）

**添加的代码**：
```csharp
// d. Update Player State (Prevent further evolution this turn)
playerState.CanEvolve = false;
_logger.LogDebug("[GameService:{GameId}] Player {PlayerId} CanEvolve flag set to false for the rest of the turn.", gameId, playerId);

// CRITICAL FIX: Send CanEvolve state update to frontend
// Since CanEvolve changed, we need to notify the frontend immediately
// We'll piggyback on the EP update event since it already handles canEvolve logic in frontend
var canEvolveUpdateEvent = new EpUpdateEventDto(playerId, playerState.CurrentEP, playerState.MaxEP);
context.Events.Add(canEvolveUpdateEvent);
_logger.LogDebug("[GameService:{GameId}] Added additional EpUpdate event to sync CanEvolve=false state to frontend.", gameId);
```

### 修复3：前端EP更新逻辑优化

**文件**：`src/gameManager.js`
**位置**：第1442-1457行（`handleEpUpdate` 函数）

**优化的逻辑**：
```javascript
// CRITICAL FIX: Update canEvolve flag based on EP availability
// Player can evolve if they have unlocked evolution (MaxEP > 0) and have EP available (CurrentEP > 0)
// IMPORTANT: If this EP update comes after evolution, the backend has already set CanEvolve=false
// So we need to respect the backend's decision rather than recalculating
const calculatedCanEvolve = playerToUpdate.maxEP > 0 && playerToUpdate.ep > 0;

// For now, let's use the calculated value but add logging to track discrepancies
const previousCanEvolve = playerToUpdate.canEvolve;
playerToUpdate.canEvolve = calculatedCanEvolve;

// Log if there's a discrepancy (this might happen after evolution when backend sets CanEvolve=false)
if (previousCanEvolve !== calculatedCanEvolve) {
    console.log(`%c[EP_UPDATE_CANEVOLVE_DEBUG] CanEvolve changed: ${previousCanEvolve} -> ${calculatedCanEvolve} (EP: ${playerToUpdate.ep}/${playerToUpdate.maxEP})`, 'color: orange; font-weight: bold;');
}
```

## 修复后的工作流程

### 1. 进化解锁
- 后端在正确回合设置EP和 `CanEvolve = true`
- 前端通过 `TurnStarted` 事件接收状态
- 前端正确映射 `CanEvolve` 到 `canEvolve`

### 2. 进化按钮显示
- UI检查 `playerState.canEvolve`（已修复属性名）
- 满足条件时显示进化按钮

### 3. 进化点击验证
- 前端 `evolveCard` 函数检查 `playerState.canEvolve`（已修复）
- 验证通过后发送进化请求到后端

### 4. 后端进化处理
- 后端执行进化逻辑
- 设置 `CanEvolve = false`（每回合只能进化一次）
- 发送额外的 `EpUpdateEvent` 同步状态到前端

### 5. 前端状态更新
- 接收 `EpUpdateEvent` 并更新EP值
- 重新计算 `canEvolve` 状态
- 触发UI重新渲染，隐藏进化按钮

## 影之诗进化规则确认

根据用户确认，影之诗的进化规则是：
- **每回合只能进化一次**
- **先手玩家**：第5回合开始可进化，最多2点EP
- **后手玩家**：第4回合开始可进化，最多3点EP
- **EP消耗**：每次进化消耗1点EP，不会自动回复
