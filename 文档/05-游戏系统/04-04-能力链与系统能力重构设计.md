# 能力链与系统能力重构设计 (V1.2 - 最终方案)

## 1. 概述

### 1.1. 背景与目标

本文档旨在明确 `ChainedAbilities` 机制的最终设计与实现方案。经过深入讨论，我们确定了将能力链的配置锚点放在 `EffectConfig` 上，并采用“生成时填充”（Early Binding）的策略来创建和关联链式能力实例，以兼顾灵活性和实现简洁性。

**核心目标:**

1.  **固化 `ChainedAbilities` 的数据模型**，将其置于 `EffectConfig` 中。
2.  **明确“生成时填充”的实现方案**，即在创建 `Effect` 实例时，就根据 `EffectConfig` 创建并附加对应的链式 `IAbility` 实例。
3.  **提供清晰的实现流程图和代码指引**。
4.  为后续修复调度（Mulligan）流程等依赖能力链的BUG提供清晰的架构指导。

## 2. 最终架构决策

### 2.1. `ChainedAbilities` 的位置

`ChainedAbilities` 属性最终确定放置在 **`EffectConfig`** 类中。

*   **`EffectConfig.cs`**:
    ```csharp
    public class EffectConfig
    {
        // ... 其他属性
        public List<AbilityConfig> ChainedAbilities { get; set; } = new();
    }
    ```

### 2.2. 运行时能力链的载体

为了在运行时传递能力链，`Effect` 类将直接持有一个 `IAbility` 实例的列表。

*   **`Effect.cs`**:
    ```csharp
    public class Effect
    {
        // ... 其他属性
        public List<IAbility> ChainedAbilities { get; set; } = new();
    }
    ```

### 2.3. 实现时机：生成时填充 (Early Binding)

我们采纳“生成时填充”方案。该方案的核心在于，`GameContext` 在传递给任何能力或效果执行器时，总是包含最新的游戏状态。这使得我们可以在创建 `Effect` 的那一刻就安全地创建其后续的链式能力实例，而不用担心状态过时。

## 3. 实现方案

### 3.1. 核心流程

**流程图 (Mermaid)**:

```mermaid
    ... 游戏循环继续 ...

```

### 3.2. `Ability.CreateEffectsAsync` 的修改

数据驱动的 `Ability` 类将是实现“生成时填充”的关键。

*   **`Ability.cs`**:
    ```csharp
    public async Task<List<Effect>> CreateEffectsAsync(GameContext context)
    {
        var resultingEffects = new List<Effect>();
        // ... (条件检查、目标解析等) ...

        foreach (var effectConfig in sortedEffectConfigs)
        {
            var effectRequest = new Effect(
                effectConfig,
                context.RequestingPlayerId,
                targetIds,
                this.RuntimeId,
                context.TriggeringEvent?.EventId ?? Guid.Empty,
                this.SourceCard?.InstanceId
            );

            // --- 核心修改：生成时填充能力链 ---
            if (effectConfig.ChainedAbilities.Any())
            {
                var abilityManager = context.GetRequiredService<AbilityManager>(); // 从GameContext获取服务
                foreach (var chainedConfig in effectConfig.ChainedAbilities)
                {
                    // 利用现有方法创建链式能力的实例
                    var chainedAbility = abilityManager.CreateAbilityFromConfig(chainedConfig, this.SourceCard);
                    if (chainedAbility != null)
                    {
                        effectRequest.ChainedAbilities.Add(chainedAbility);
                    }
                }
            }
            // --- 修改结束 ---

            resultingEffects.Add(effectRequest);
        }

        return resultingEffects;
    }
    ```
    **注意**: 为了让 `Ability` 类能访问 `AbilityManager`，我们需要调整依赖注入，可能会通过在 `GameContext` 中添加 `IServiceProvider` 来实现。

### 3.3. `GameService.ProcessEffectQueueForGameAsync` 的修改

`GameService` 的逻辑变得非常简单。

*   **`GameService.cs`**:
    ```csharp
    // 在 ProcessEffectQueueForGameAsync 的 while 循环内
    
    var effectRequest = _effectQueueService.GetNextEffectRequest(gameId);
    // ... (构建 gameContext, 执行 effectRequest) ...
    var effectResult = await effectExecutor.ExecuteEffectAsync(effectConfig, gameContext);

    // --- 核心修改：处理已附加的链式能力 ---
    if (effectRequest.ChainedAbilities.Any())
    {
        _logger.LogInformation("Effect {EffectType} completed and has {Count} chained abilities. Processing them...", effectConfig.Type, effectRequest.ChainedAbilities.Count);
        
        var chainedEffects = new List<Effect>();
        foreach (var chainedAbility in effectRequest.ChainedAbilities)
        {
            // 注意：此处使用的 gameContext 是最新的
            var newEffects = await chainedAbility.CreateEffectsAsync(gameContext);
            chainedEffects.AddRange(newEffects);
        }

        if (chainedEffects.Any())
        {
            foreach(var effect in chainedEffects)
            {
                await _effectQueueService.EnqueueEffectRequestAsync(gameId, effect);
            }
        }
    }
    // --- 修改结束 ---

    // 继续处理 effectResult.GeneratedEvents...
    ```
