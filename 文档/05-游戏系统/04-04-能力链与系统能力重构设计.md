# 能力链与系统能力重构设计 (V1.2 - 最终方案)

## 1. 概述

### 1.1. 背景与目标

本文档旨在明确 `ChainedAbilities` 机制的最终设计与实现方案。经过深入讨论，我们确定了将能力链的配置锚点放在 `EffectConfig` 上，并采用“生成时填充”（Early Binding）的策略来创建和关联链式能力实例，以兼顾灵活性和实现简洁性。

**核心目标:**

1.  **固化 `ChainedAbilities` 的数据模型**，将其置于 `EffectConfig` 中。
2.  **明确“生成时填充”的实现方案**，即在创建 `Effect` 实例时，就根据 `EffectConfig` 创建并附加对应的链式 `IAbility` 实例。
3.  **提供清晰的实现流程图和代码指引**。
4.  为后续修复调度（Mulligan）流程等依赖能力链的BUG提供清晰的架构指导。

## 2. 最终架构决策

### 2.1. `ChainedAbilities` 的位置

`ChainedAbilities` 属性最终确定放置在 **`EffectConfig`** 类中。

*   **`EffectConfig.cs`**:
    ```csharp
    public class EffectConfig
    {
        // ... 其他属性
        public List<AbilityConfig> ChainedAbilities { get; set; } = new();
    }
    ```

### 2.2. 运行时能力链的载体

为了在运行时传递能力链，`Effect` 类将直接持有一个 `IAbility` 实例的列表。

*   **`Effect.cs`**:
    ```csharp
    public class Effect
    {
        // ... 其他属性
        public List<IAbility> ChainedAbilities { get; set; } = new();
    }
    ```

### 2.3. 实现时机：生成时填充 (Early Binding)

我们采纳“生成时填充”方案。该方案的核心在于，`GameContext` 在传递给任何能力或效果执行器时，总是包含最新的游戏状态。这使得我们可以在创建 `Effect` 的那一刻就安全地创建其后续的链式能力实例，而不用担心状态过时。

## 3. 实现方案

### 3.1. 核心流程

**流程图 (Mermaid)**:
```mermaid
sequenceDiagram
    participant ParentAbility as "父能力实例 (IAbility)"
    participant Effect as "Effect对象"
    participant AbilityManager
    participant GameService

    ParentAbility->>ParentAbility: 1. CreateEffectsAsync()
    Note over ParentAbility: 读取 EffectConfig
    
    alt 如果 EffectConfig 中有 ChainedAbilities
        ParentAbility->>+AbilityManager: 2. 为每个配置创建链式IAbility实例
        AbilityManager-->>-ParentAbility: 3. 返回链式IAbility实例列表
        ParentAbility->>Effect: 4. 将IAbility实例列表存入Effect.ChainedAbilities
    end

    Note over ParentAbility: 5. Effect对象创建完毕并入队

    ... 游戏循环继续 ...

    GameService->>GameService: 10. 从队列取出并执行Effect
    Note over GameService: 检查 effect.ChainedAbilities 是否有内容
    
    alt 如果 effect.ChainedAbilities 不为空
        GameService->>GameService: 11. 遍历链式IAbility实例列表
        loop for each chainedAbility in list
            GameService->>GameService: 12. 为 chainedAbility 创建新Effects并入队
        end
    end
```

### 3.2. `Ability.CreateEffectsAsync` 的修改（当前实现）

数据驱动的 `Ability` 类将是实现“生成时填充”的关键。

*   **`Ability.cs`**（精简示意，详见实际代码）：
    ```csharp
    // CreateEffectsAsync 会为每个 EffectConfig 生成一个 Effect 请求
    // 并在生成时（Early Binding）把 EffectConfig.ChainedAbilities 实例化为运行时 IAbility，附加到 effect.ChainedAbilities。
    var effectRequest = new Effect(effectConfig, ...);

    if (effectConfig.ChainedAbilities.Any())
    {
        var abilityFactory = context.ServiceProvider.GetRequiredService<IAbilityFactory>();
        var chainedAbilities = abilityFactory.CreateAbilities(this.SourceCard, effectConfig.ChainedAbilities);
        effectRequest.ChainedAbilities.AddRange(chainedAbilities);
    }
    ```

### 3.3. 事务引擎执行连锁能力（当前实现）

当前代码已迁移至事务处理模型，由 `GameActionTransactionService` 在执行单个 `Effect` 后立刻处理 `effect.ChainedAbilities`：

- 实现位置：`Server/Services/GameActionTransactionService.cs`（`ProcessEffectAsync` / `ProcessChainedAbilitiesAsync`）
- 触发事件：连锁能力以 `EffectCompletedEvent` 作为 `TriggeringEvent`，可直接读取 `ResolvedTargets` 与 `Outputs`。

精简示意：
```csharp
var effectResult = _effectExecutor.ExecuteEffect(effect, effectContext);

// 优先处理连锁能力（不进入全局队列）
await ProcessChainedAbilitiesAsync(effect, effectContext, effectResult, processedEvents);

// 然后再递归处理 effectResult.GeneratedEvents（包含 EffectCompletedEvent）
foreach (var newEvent in effectResult.GeneratedEvents)
{
    await ProcessEventRecursivelyAsync(effectContext, newEvent, processedEvents);
}
```

### 3.4. 连锁能力复用“首次选择目标”

为降低 DSL 学习成本并支持“先选目标 → 连锁能力根据该目标分支”，当前推荐两种访问方式：

1. **条件/判断 DSL**：使用 `context.selectedTargets` 读取父效果携带的目标列表（连锁能力处理阶段会保留父效果上下文）。
2. **目标选择 DSL（Query/TargetConfig）**：使用 `AbilityTargets.previous` 访问父效果目标池，供连锁能力在自身目标解析中引用（例如从父目标中二次筛选）。
