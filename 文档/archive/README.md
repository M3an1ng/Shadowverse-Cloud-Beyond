# Archive - 历史文档

## 说明

本目录包含项目演进过程中的历史文档，这些文档已被新的文档系统替代，但保留用于参考和历史追溯。

## 迁移说明

### 原文档结构 (docs/)
原有的 `docs/` 目录包含了项目从初期到重构完成的所有文档，采用了较为分散的组织方式。

### 新文档结构 (文档/)
新的 `文档/` 目录采用了更加系统化的分层组织方式：

```
文档/
├── 01-项目概览/          # 替代原有的项目概述文档
├── 02-后端架构/          # 整合原有的后端设计文档
├── 03-前端架构/          # 整合原有的前端设计文档
├── 04-数据库设计/        # 整合原有的数据库相关文档
├── 05-游戏系统/          # 整合原有的游戏机制文档
├── 06-API文档/           # 整合原有的API设计文档
├── 07-开发指南/          # 整合原有的开发规范文档
└── Archive/              # 本目录，存放历史文档
```

### 保留在Archive中的文档类型

1. **历史版本文档**: 如 `M4_数据库集成设计_V1.0.md` 等版本化文档
2. **调试记录**: `调试记录/` 目录下的问题追踪文档
3. **临时文档**: `临时/` 目录下的临时性文档
4. **工作备忘录**: 开发过程中的临时记录
5. **已解决问题**: 历史问题的解决方案记录

## 使用建议

### 查找历史信息
如果需要查找特定功能的历史实现细节或设计决策，可以在Archive中搜索相关文档。

### 问题排查
遇到问题时，可以参考 `调试记录/` 和 `已解决问题归档/` 中的历史解决方案。

### 设计参考
新功能开发时，可以参考 `技术文档/` 和 `设计文档/` 中的历史设计思路。

## 文档状态说明

- **[DEPRECATED]**: 已废弃，被新文档替代
- **[ARCHIVED]**: 已归档，保留用于历史参考
- **[REFERENCE]**: 参考文档，仍有参考价值

## 注意事项

1. **不建议直接使用**: Archive中的文档可能包含过时信息，建议优先参考新文档系统
2. **版本差异**: 历史文档可能反映的是旧版本的实现，与当前代码可能不一致
3. **完整性**: 某些历史文档可能不完整或包含临时性内容
