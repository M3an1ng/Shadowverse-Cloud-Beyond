## 🗂️ 归档原则

### 归档条件
文档满足以下条件之一时会被归档：

1. **功能已完成：** 功能已实现并有更完整的文档替代
2. **设计已过时：** 设计方案已被新方案替代
3. **临时性质：** 临时调试记录在问题解决后归档
4. **重复内容：** 内容已被合并到其他文档中

### 保留原则
以下类型的文档会被保留在归档中：

1. **历史价值：** 记录重要的开发过程和决策
2. **参考价值：** 可能对未来开发有参考意义
3. **完整性：** 保持项目开发历史的完整性
4. **学习价值：** 对新开发者了解项目演进有帮助

## 🔄 归档管理

### 定期清理
- **频率：** 每个主要功能完成后
- **范围：** 临时调试文档和过时设计文档
- **保留：** 有历史价值的重要文档

### 文档状态更新
- **DEPRECATED：** 标记已废弃的文档
- **COMPLETED：** 标记已完成的功能文档
- **ARCHIVED：** 标记已归档的文档

### 引用更新
归档文档时需要：
1. 更新主文档中的引用链接
2. 在归档文档中添加替代文档链接
3. 更新相关的导航文档
