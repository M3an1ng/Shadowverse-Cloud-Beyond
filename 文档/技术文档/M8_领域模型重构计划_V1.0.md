# 领域模型重构计划 (M8_V1.0) - 基于 BoardEntityState 继承

**版本:** 1.0
**日期:** 2025-05-26
**作者:** Project Assistant AI

## 1. 目标

- 重构领域模型，引入抽象基类 `BoardEntityState`，以统一处理场上的单位、护符和领袖。
- 创建 `UnitState`, `AmuletState`, `LeaderState` 作为 `BoardEntityState` 的派生类。
- 调整 `PlayerState` 和 `GameState` 以适应新的模型结构，特别是：
  - 从 `PlayerState` 中移除任何直接与 Leader 健康值相关的属性（如果存在）。
  - 在 `GameState` 中分别管理 Leader、场上单位和场上护符，取代原有的 `PlayerXBoard` 列表。

  ```csharp
  // File: Server/Domain/Entities/LeaderState.cs
  using System; // For Math.Min

  namespace ShadowverseBeyond.Server.Domain.Entities
  {
      /// <summary>
      /// Represents the state of a Player's Leader on the board.
      /// Treated as a special type of BoardEntityState.
      /// </summary>
      public class LeaderState : BoardEntityState
      {
          // Leader-specific properties (Health)
          public int CurrentHealth { get; set; }
          public int MaxHealth { get; set; } // Can be modified by effects?

          // Constructor
          public LeaderState(string instanceId, string ownerPlayerId, int definitionId, int initialHealth)
              : base(instanceId, ownerPlayerId, definitionId)
          {
              MaxHealth = initialHealth;
              CurrentHealth = initialHealth;
          }

          // Parameterless constructor for serialization/ORM
          private LeaderState() : base() { }

          // Leader-specific methods
          public void TakeDamage(int amount)
          {
              if (amount < 0) return; // Damage shouldn't be negative
              CurrentHealth -= amount;
              // Add logic for lethal, triggering effects on damage, etc.
          }

          public void Heal(int amount)
          {
              if (amount < 0) return; // Healing shouldn't be negative
              CurrentHealth = Math.Min(CurrentHealth + amount, MaxHealth);
          }

           public void SetMaxHealth(int newMaxHealth, bool restoreToFull = false)
           {
               MaxHealth = newMaxHealth;
               if (restoreToFull)
               {
                   CurrentHealth = MaxHealth;
               }
               else
               {
                  // Ensure current health doesn't exceed new max health
                  CurrentHealth = Math.Min(CurrentHealth, MaxHealth);
               }
           }
      }
  }
  ```

## 6. 客户端状态同步与水合策略 (Client-Side State Synchronization & Hydration Strategy) - V1.0 (2025-05-27)

**背景:** 在实现前后端分离和通过 SignalR 进行实时通信的过程中，发现客户端在接收服务器状态更新（无论是完整状态还是增量事件）时，未能正确地将服务器发送的纯数据对象 (DTOs) 恢复（"水合" - Hydrate）为包含方法和预期行为的客户端 JavaScript 对象实例 (`Player`, `CardInstance`)。这导致了在后续操作中调用这些对象方法时出现 `TypeError` (例如 `gameState.activePlayer.drawCard is not a function`)。

**问题分析:**

- **`updateFullGameState` 函数:** 使用 `Object.assign` 直接将服务器 DTO 覆盖本地 `gameState`，导致 `Player` 和 `CardInstance` 对象丢失其原型链和方法。
- **`processGameEvent` 函数 (例如 `TurnEnded` 事件):** 在处理增量更新时，直接将服务器发送的 `CardDto` (如 `drawnCard`) 推入 `player.hand` 数组，同样引入了未水合的对象。并且，它依赖的 `player` 对象本身可能已在之前的 `updateFullGameState` 调用中被破坏。

**解决方案：“智能水合” (Smart Hydration)**

为了确保客户端 `gameState` 的一致性和功能完整性，采用以下策略更新 [`src/gameManager.js`](../../../src/gameManager.js) 中的状态处理逻辑：

1. **依赖引入:** 引入客户端对象工厂函数 `createPlayer` (from [`src/player.js`](../../../src/player.js)) 和 `createCardInstance` (from [`src/card.js`](../../../src/card.js))。

2. **Player 对象水合:**
    *   **查找或创建:** 遍历服务器玩家 DTOs (`serverPlayerDto`)。
    *   **匹配:** 使用 `playerId` 在当前客户端 `gameState.players` 中查找对应实例 (`clientPlayerInstance`)。
    *   **更新/创建:**
        *   **找到实例:** 更新 `clientPlayerInstance` 的数据属性（PP, EP, Health等）。对卡牌相关属性（`hand`, `field`, `graveyard`, `leaderCard`）执行“卡牌对象水合”。
        *   **未找到实例:** 使用 `createPlayer` 创建新实例，填充数据属性，执行“卡牌对象水合”，并添加到 `gameState.players`。

3. **Card 对象水合:**
    *   **创建实例:** 对每个服务器卡牌 DTO (`serverCardDto`)，调用 `createCardInstance(serverCardDto)` 创建功能完整的客户端卡牌实例 (`clientCardInstance`)。
    *   **更新列表 (`hand`, `field`, `graveyard`):** 创建一个包含所有新创建的 `clientCardInstance` 的*新数组*，并将玩家对象的相应属性指向此新数组。
    *   **更新单个卡牌 (`leaderCard`, `drawnCard`, etc.):** 将玩家对象的相应属性直接指向新创建的 `clientCardInstance`。
    *   **更新现有卡牌状态 (事件驱动):** 对于仅更新现有卡牌状态的事件（如 `AttackOccurred`, `UnitEvolved`, `StatChange`），先通过 `findCardInstanceByUid` 找到客户端实例，然后仅更新其数据属性（`currentHealth`, `currentAttack`, `isEvolved` 等），**避免**使用 `Object.assign` 覆盖整个实例。

**实施细节:**

- **`updateFullGameState`:** 彻底移除 `Object.assign(gameState, serverState)`，改为实现上述水合逻辑。先更新顶层简单属性，然后处理 `players` 及其包含的卡牌，最后更新 `activePlayer`/`opponentPlayer` 引用。
- **`processGameEvent`:**
  - 修改所有处理玩家状态或卡牌状态的 `case`。
    - 确保更新属性时操作的是正确的 `Player` 或 `CardInstance` 实例。
    - 使用 `createCardInstance` 处理所有新进入游戏状态的卡牌（如 `drawnCard`）。
    - 对于状态更新（如攻击结果 `attackerState`, `targetState`），显式更新实例的属性，而非覆盖实例。
