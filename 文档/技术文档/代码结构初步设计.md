# 代码结构初步设计 V0.2 (模块化方案)

**变更记录:** V0.2 采用了 ES Modules 进行 JavaScript 代码模块化，以提高可维护性和可扩展性，取代 V0.1 的单 `script.js` 文件方案。

本文档定义了《影之诗》网页版 Demo (阶段一) 采用模块化设计后的文件和代码组织结构。

## 1. 根目录结构

```
/Shadowverse-beyond/
├── index.html             # 主 HTML 文件，承载游戏界面
├── style.css              # CSS 样式文件，负责界面美化
├── /data/
│   └── card_data.json     # 卡牌数据库 (初期使用 JSON)
├── /src/                  # JavaScript 模块目录
│   ├── main.js            # JS 入口文件，协调各模块
│   ├── gameManager.js     # 核心游戏状态与逻辑管理
│   ├── turnManager.js     # 回合流程控制
│   ├── cardManager.js     # 卡牌数据加载与实例创建
│   ├── player.js          # 玩家/AI 数据结构与方法
│   ├── ui.js              # DOM 操作与界面渲染
│   └── ai.js              # AI 决策逻辑
└── /文档/                  # 项目文档目录
    ├── 项目初步构想与范围定义书.md
    ├── 项目整体任务清单.md
    └── 代码结构初步设计.md
    └── 工作备忘录.md
    └── (其他文档...)
```

## 3. 文件/模块说明

### 3.1 `index.html`

- **职责**:
  - 定义网页的基本结构 (HTML5)。
  - 包含游戏界面的主要区域划分 (ID 如: `#game-container`, `#player1-hand`, `#player1-field` 等保持不变)。
  - 链接 `style.css`。
  - **重要:** 链接 `src/main.js` 并 **必须** 添加 `type="module"` 属性，以启用 ES Module 加载。`<script src="src/main.js" type="module" defer></script>`
- **关键元素**: 同 V0.1 设计。

### 3.2 `style.css`

- **职责**: 同 V0.1 设计 (定义视觉样式和布局)。
- **关键样式类**: 同 V0.1 设计。

### 3.3 `/data/card_data.json`

- **职责**: 同 V0.1 设计 (存储卡牌基础定义)。
- **结构**: 同 V0.1 设计。

### 3.4 `/src/` 目录 (JavaScript Modules)

#### 3.4.1 `main.js` (入口模块)

- **职责**:
  - 整个 JavaScript 应用的入口点。
  - **导入 (import)** 其他所有需要的核心模块。
  - 初始化游戏 (例如，调用 `cardManager.loadCards()` 然后 `gameManager.initGame()`)。
  - 设置主要的事件监听器 (如结束回合按钮)，并将事件分发给相应的管理器 (如调用 `turnManager.endTurn()`)。
  - 启动初始渲染 (调用 `ui.renderGame()`)。
- **依赖**: `gameManager`, `turnManager`, `cardManager`, `ui`, `ai` (可能间接通过 gameManager)。

#### 3.4.2 `gameManager.js`

- **职责**:
  - **导出 (export)** 核心游戏状态 `gameState` (或提供访问状态的函数)。
  - **导出** 核心游戏逻辑函数，供 `main.js` 或 `ui.js` 调用 (如 `playCard`, `initiateAttack`, `selectAttackTarget`, `evolveCard`, `checkGameOver`)。
  - 内部可能 **导入** `player.js`, `cardManager.js`, `turnManager.js`, `ai.js` 来执行具体逻辑。
  - 管理游戏阶段 (`gamePhase`)。
- **状态**: 包含 `players`, `currentPlayerId`, `turnNumber`, `gamePhase`, `gameOver`, `winner`, `selectedAttackerUid` 等。

#### 3.4.3 `turnManager.js`

- **职责**:
  - **导出** `startTurn` 和 `endTurn` 函数。
  - 管理回合特定的逻辑：资源回复、抽卡、重置攻击状态、触发回合开始/结束效果（未来）。
  - 内部可能 **导入** `gameManager` (访问和修改状态)、`player.js` (调用抽卡)、`ai.js` (触发 AI 行动)、`ui.js` (调用渲染)。
- **依赖**: `gameManager`, `player`, `ai`, `ui`.

#### 3.4.4 `cardManager.js`

- **职责**:
  - **导出** `loadCards` 函数 (异步加载 `card_data.json`)。
  - **导出** `getCardDefinition(cardId)` 函数。
  - **导出** `createCardInstance(cardDefinition)` 函数 (创建包含 `uid`, `currentHealth` 等运行时属性的卡牌实例)。
  - 存储加载后的卡牌数据库 (`cardDatabase`)。
- **依赖**: 无其他 JS 模块，但会 `fetch` `data/card_data.json`。

#### 3.4.5 `player.js`

- **职责**:
  - **导出** `Player` 类或创建玩家对象的工厂函数。
  - 定义玩家的核心属性 (`id`, `health`, `pp`, `maxPp`, `ep`, `maxEp`, `deck`, `hand`, `field`, `graveyard`, `isAI`)。
  - 可能包含玩家自身的方法，如 `drawCard(count)`。
- **依赖**: 可能导入 `cardManager` (如果 `drawCard` 内部需要创建实例)。

#### 3.4.6 `ui.js`

- **职责**:
  - **导出** `renderGame` 函数。
  - **导出** (或内部使用) 创建各种 UI 元素的辅助函数 (如 `createCardElement`)。
  - 包含所有直接操作 DOM 的代码。
  - 根据从 `gameManager` 获取的状态来渲染界面。
  - **不包含游戏核心逻辑**，只负责展示和触发事件。
  - 内部会 **导入** `gameManager` (获取状态)、`cardManager` (获取卡牌定义用于渲染)。
- **依赖**: `gameManager`, `cardManager`.

#### 3.4.7 `ai.js`

- **职责**:
  - **导出** `runAILogic` 函数。
  - 包含 AI 的决策算法 (出牌、攻击、进化)。
  - 内部会 **导入** `gameManager` (获取游戏状态，调用游戏动作)。
- **依赖**: `gameManager`.

## 4. ES Modules 关键点

- **`export`**: 在模块文件 (如 `gameManager.js`) 中，使用 `export` 关键字使变量、函数或类能够被其他模块访问。
  ```javascript
  // gameManager.js
  export let gameState = {
    /* ... */
  };
  export function playCard(cardUid) {
    /* ... */
  }
  ```
- **`import`**: 在需要使用其他模块功能的 文件 (如 `main.js`) 中，使用 `import` 关键字引入。路径通常相对于当前文件。
  ```javascript
  // main.js
  import { gameState, playCard } from "./gameManager.js";
  import { renderGame } from "./ui.js";
  ```
- **`index.html`**: 必须在 `<script>` 标签中添加 `type="module"`。
  ```html
  <script src="src/main.js" type="module" defer></script>
  ```
- **本地运行**: 直接在浏览器中打开使用 ES Modules 的 `index.html` 文件可能会遇到 CORS 策略问题。通常需要通过一个简单的本地服务器来运行 (VS Code 的 Live Server 插件可以解决这个问题)。

## 5. 扩展性考虑

- 这个模块化结构比单文件方案提供了更好的基础。
- 未来可以进一步细化模块，例如将效果处理 (`effectExecutor.js`)、战斗计算 (`combat.js`) 等单独抽离。
- 更容易引入单元测试框架。
