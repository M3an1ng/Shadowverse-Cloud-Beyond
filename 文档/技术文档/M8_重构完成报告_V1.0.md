## 1. 重构概述

本次重构采用了与原计划不同但更优雅的方案：**统一卡牌实例模型**。我们创建了单一的 `CardInstance` 类来替代复杂的继承层次结构，实现了更简洁和灵活的领域模型。

## 2. 实际实施方案

### 2.1 核心变更

#### ✅ 新增 `CardInstance` 实体
- **路径:** `Server/Domain/Entities/CardInstance.cs`
- **功能:** 统一处理所有类型的卡牌实例（Leader、Follower、Spell、Amulet）
- **特点:**
  - 实现 `IBoardEntityState` 接口
  - 支持所有区域（手牌、战场、牌库、墓地等）
  - 包含类型检查辅助方法（`IsLeader`、`IsFollower` 等）
  - 包含区域检查辅助方法（`IsInHand`、`IsOnField` 等）

#### ✅ 删除复杂继承结构
删除了以下实体类：
- `BoardEntityState.cs` - 抽象基类
- `LeaderState.cs` - 领袖状态
- `UnitState.cs` - 单位状态  
- `AmuletState.cs` - 护符状态

#### ✅ 更新 `PlayerState` 实体
- 移除 `LeaderHealth` 和 `LeaderMaxHealth` 属性
- 更新卡牌集合使用 `CardInstance` 而非 `CardState`
- 移除冗余的 `Field` 属性（现在由 `GameState` 统一管理）

#### ✅ 更新 `GameState` 实体
- 使用 `CardInstance` 类型的 `Player1Leader` 和 `Player2Leader`
- 使用统一的 `Player1Field` 和 `Player2Field` 列表
- 更新 `FindEntityByUid` 方法支持新的结构

#### ✅ 解决命名冲突
- 统一使用 `Server/Dtos/CardInstanceDto.cs` 中的 `CardZone` 枚举
- 添加 `Playing` 区域支持临时卡牌状态

### 3.2 关键优势

1. **统一性**: 所有卡牌实例使用同一个类，消除类型转换复杂性
2. **灵活性**: 单个实例可以在不同区域间移动，无需类型转换
3. **可扩展性**: 新增卡牌类型只需添加类型检查方法
4. **简洁性**: 减少了大量样板代码和继承关系
5. **一致性**: 与 DTO 层的 `CardInstanceDto` 保持概念一致
