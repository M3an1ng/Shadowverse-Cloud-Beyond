## 1. 目标

本次迭代 (M4) 的核心目标是替换当前后端 `/api/cards` 端点直接读取 `card_data.json` 文件的方式，转而使用 SQLite 数据库和 Entity Framework Core (EF Core) 来持久化和读取卡牌定义数据，为后续的卡牌管理功能奠定基础。

## 2. 技术选型与确认细节

- **数据库:** SQLite (文件型数据库，适用于开发和早期阶段)
- **ORM:** Entity Framework Core (EF Core)
- **架构模式:** 遵循分层架构 (Presentation, Application, Domain, Infrastructure)，使用 Repository 模式和服务层。
- **数据库文件位置:** `./Server/shadowverse.db`
- **数据填充:** 首次运行时，从 `./data/card_data.json` 自动填充数据。
- **服务层:** 创建独立的 `CardService` (应用层) 负责处理卡牌数据相关的业务逻辑。
- **复杂列表存储:** 对于 `CardDefinition` 中的 `Keywords`, `Effects` 等列表/复杂类型属性，初期使用 **JSON 字符串** 存储在主表列中。
  - **【重要记录】:** `Effects` 属性未来可能需要更复杂的结构化存储（如关联表或更复杂的 JSON 结构）以支持游戏逻辑解析，当前 JSON 字符串方案仅为初期简化实现，需在后续迭代中重构。

## 8. 数据填充 (Seeding)

在 `Program.cs` 中添加或调用一个 Seeding 方法，确保在数据库首次创建或为空时，从 [`data/card_data.json`](data/card_data.json) 读取数据并插入。

```csharp
// Seeding 方法 (可以放在 Program.cs 底部或单独的类中)
async Task SeedDatabase(IServiceProvider serviceProvider)
{
    using var scope = serviceProvider.CreateScope(); // Use the passed IServiceProvider to create scope
    var context = scope.ServiceProvider.GetRequiredService<ApplicationDbContext>(); // Correct DbContext name
    var logger = scope.ServiceProvider.GetRequiredService<ILogger<Program>>(); // Get logger

    // 检查数据库是否已经有数据
    if (await context.CardDefinitions.AnyAsync())
    {
        logger.LogInformation("Database already seeded.");
        return; // DB has been seeded
    }

    logger.LogInformation("Seeding database...");

    try
    {
        // 读取 JSON 文件
        var jsonFilePath = Path.Combine(AppContext.BaseDirectory, "..", "..", "..", "data", "card_data.json"); // Adjust path relative to executable in bin/Debug...
        if (!File.Exists(jsonFilePath)) {
             jsonFilePath = Path.Combine(AppContext.BaseDirectory, "data", "card_data.json"); // Try path relative to executable for deployment scenario
        }

         if (!File.Exists(jsonFilePath)) {
             logger.LogError($"Seed file not found at expected locations based on AppContext.BaseDirectory: {AppContext.BaseDirectory}");
            // Attempt relative path from workspace root (might work during development with 'dotnet run' from root)
            var workspaceRelativePath = Path.Combine(Directory.GetCurrentDirectory(), "data", "card_data.json");
            if (File.Exists(workspaceRelativePath)) {
                jsonFilePath = workspaceRelativePath;
                logger.LogInformation($"Found seed file using workspace relative path: {jsonFilePath}");
            } else {
                logger.LogError($"Seed file also not found at workspace relative path: {workspaceRelativePath}");
                throw new FileNotFoundException("card_data.json seed file not found.");
            }
        }


        var jsonData = await File.ReadAllTextAsync(jsonFilePath);

        // 定义一个临时的 DTO 来匹配 JSON 结构
        // Note: JSON keys are typically lowercase in JavaScript world
        public class CardDataDto
        {
            public string? id { get; set; }
            public string? name { get; set; }
            public int cost { get; set; }
            public string? type { get; set; } // "Follower", "Spell", "Amulet"
            public int? attack { get; set; }
            public int? health { get; set; }
            public int? evoAttack { get; set; }
            public int? evoHealth { get; set; }
            public string? description { get; set; }
            public string? evoDescription { get; set; }
            public List<string>? keywords { get; set; }
            public List<object>? effects { get; set; } // Use object for flexibility, will serialize to JSON string
            public bool? canEvolve { get; set; } // Nullable to handle missing field
        }


        var options = new JsonSerializerOptions
        {
            PropertyNameCaseInsensitive = true // Handles potential case differences
        };
        var cardsDto = JsonSerializer.Deserialize<List<CardDataDto>>(jsonData, options);

        if (cardsDto == null || !cardsDto.Any()) {
             logger.LogWarning("No cards deserialized from JSON data.");
            return;
        }

        // 映射到 CardDefinition 实体
        var cardDefinitions = cardsDto.Select(dto => new CardDefinition
        {
            Id = dto.id ?? throw new InvalidOperationException("Card ID cannot be null."),
            Name = dto.name ?? "Unnamed Card",
            Cost = dto.cost,
            Type = dto.type ?? "Unknown",
            Attack = dto.attack,
            Health = dto.health,
            EvoAttack = dto.evoAttack,
            EvoHealth = dto.evoHealth,
            Description = dto.description,
            EvoDescription = dto.evoDescription,
            // Serialize Keywords and Effects to JSON strings
            KeywordsJson = dto.keywords != null && dto.keywords.Any() ? JsonSerializer.Serialize(dto.keywords) : null,
            EffectsJson = dto.effects != null && dto.effects.Any() ? JsonSerializer.Serialize(dto.effects) : null,
            CanEvolve = dto.type == "Follower" // Simple logic: only followers can evolve by default
                      && (dto.evoAttack.HasValue || dto.evoHealth.HasValue) // Check if evo stats exist
                      && (dto.canEvolve ?? true) // Respect 'canEvolve' field if present, default true for followers with evo stats
        }).ToList();


        await context.CardDefinitions.AddRangeAsync(cardDefinitions);
        await context.SaveChangesAsync();
        logger.LogInformation($"Database seeded with {cardDefinitions.Count} cards.");
    }
    catch(JsonException jsonEx)
    {
        logger.LogError(jsonEx, "Error deserializing card_data.json during seeding.");
        throw; // Re-throw to indicate failure
    }
    catch (FileNotFoundException fnfEx)
    {
         logger.LogError(fnfEx, "Error finding seed file.");
        throw;
    }
    catch (Exception ex)
    {
        logger.LogError(ex, "An error occurred during database seeding.");
        throw;
    }
}

```

## 9. EF Core Migrations

1.  **安装 `dotnet-ef` 工具** (如果尚未安装):

    ```bash
    dotnet tool install --global dotnet-ef
    ```

    _(如果已安装，可尝试 `dotnet tool update --global dotnet-ef`)_

2.  **创建第一个 Migration** (在 Server 目录下执行):

    ```bash
    dotnet ef migrations add InitialCreate --project ./Server --startup-project ./Server
    ```

    - 这会根据 `ApplicationDbContext` 和 `CardDefinition` 生成迁移文件到 `Server/Data/Migrations/` 目录下。

3.  **应用 Migration** (在 `Program.cs` 中通过 `context.Database.Migrate()` 自动完成)
    - 或者手动应用 (在 Server 目录下执行):
      ```bash
      dotnet ef database update --context ApplicationDbContext --project ./Server --startup-project ./Server # Recommended: Specify context
      ```

  - 随后遇到 `Program.cs` 中的编译错误 (CS1061: 找不到 OpenAPI 方法, CS0246: 找不到 `CardDefinition` 类型)，通过以下方式解决：
    - 添加 `Swashbuckle.AspNetCore` NuGet 包。
    - 修正 `Program.cs` 中的 OpenAPI/Swagger 服务注册和中间件调用代码 (`AddEndpointsApiExplorer`, `AddSwaggerGen`, `UseSwagger`, `UseSwaggerUI`)。
    - 移除 `Program.cs` 文件末尾与实体类冲突的 `CardDefinition` record 定义。
    - 在 `Program.cs` 顶部添加 `using Server.Domain.Entities;`。
  - 成功构建后，基于简化的 `CardDefinition` (注释掉了 `Effects` 相关代码) 创建了第一个迁移 `InitialCreate`。
  - 恢复 `CardDefinition.cs` 中的 `Effects` 相关代码后，再次 `dotnet build` 成功。
  - 添加了第二个迁移 `AddCardEffects` 以包含 `EffectsJson` 列，成功执行。
  - 执行 `dotnet ef database update` 时，因项目中存在额外的 `TemporaryDbContext.cs` 而失败 (错误：More than one DbContext)。
  - 通过添加 `--context ApplicationDbContext` 参数成功执行 `dotnet ef database update`，应用了两个迁移。
  - 最后删除了多余的 `TemporaryDbContext.cs` 文件，并通过 `dotnet build` 确认无影响。
- **结论:** 数据库模式已根据设计（通过两次迁移）成功创建并应用。后续 EF Core 相关命令建议添加 `--context ApplicationDbContext` 参数以避免潜在歧义。数据填充 (Seeding) 逻辑已通过将代码重构至 `Server/Infrastructure/Data/DataSeeder.cs` 文件中实现 (2025-05-24)，并通过了编译验证。M4 的后续步骤是实现 Repository 和修改 Application 层以使用数据库。

## 11. 未来考虑与扩展点

- **`EffectsJson` 处理:** 当前存储为 JSON 字符串不利于后端逻辑直接查询和处理效果。未来应设计更具体的 `Effect` 实体/表结构，或使用更强大的 JSON 查询功能 (如 PostgreSQL JSONB 或 EF Core 7+ 的 JSON Columns 功能，但 SQLite 支持有限)。
- **性能:** 对于大量卡牌，直接 `GetAllAsync` 可能效率不高。后续需要添加分页、过滤、搜索等功能。
- **错误处理:** 增强 Repository 和 Service 层中的错误处理逻辑。
- **DTO 映射:** 在 Service 层或 Controller 层使用 AutoMapper 或手动映射，将 `CardDefinition` 实体映射到专门的 DTOs，避免直接暴露数据库实体给 API。
- **测试:** 添加单元测试和集成测试。
