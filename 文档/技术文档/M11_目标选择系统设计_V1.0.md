# M11: 目标选择系统设计 V1.0

## 1. 概述

本文档详细描述卡牌能力系统中 **目标选择 (Target Selection)** 的设计理念、数据结构、配置方式以及实现策略。

目标选择系统负责在卡牌能力触发并通过条件检查后，根据预定义的规则，从当前游戏状态中筛选出能力将要影响的一个或多个目标（如卡牌、玩家等）。其核心目标是提供一个灵活、可配置且高效的目标筛选机制。

## 2. 核心概念与设计原则

### 2.1 核心概念

*   **目标 (Target):** 能力效果可以作用的游戏实体，包括但不限于卡牌实例 (CardInstance，场上、手牌、牌库、墓地)、玩家状态 (PlayerState)、甚至可能是抽象的游戏概念（如某个区域、计数器）。
*   **选择器 (Selector):** 定义了如何从游戏状态中筛选出特定目标的规则集合。一个选择器封装了目标类型、来源范围、筛选条件、数量限制等逻辑。
*   **过滤器 (Filter):** 用于根据目标的具体属性或状态进一步细化筛选过程的条件。过滤器通常是选择器的一部分。
*   **目标上下文 (TargetSelectionContext):** 执行目标选择时所需的环境信息，如当前游戏状态、能力来源、触发事件等。
*   **目标池 (Target Pool):** 在应用过滤器之前的潜在目标集合。
*   **选定目标 (Selected Targets):** 经过选择器完整处理后最终确定的目标列表。

### 2.2 设计原则

*   **配置驱动 (Configuration-Driven):** 目标选择逻辑应主要通过数据配置（推荐 JSON）来定义，而不是硬编码在代码中，以方便卡牌设计和平衡调整。
*   **灵活性与可扩展性 (Flexibility & Extensibility):** 系统应能支持各种复杂的目标选择场景，并易于添加新的目标类型、筛选条件和选择模式。
*   **关注点分离 (Separation of Concerns):**
    *   目标选择逻辑应与条件评估逻辑、效果执行逻辑清晰分离。
    *   目标选择器本身应专注于“找到”目标，具体的筛选条件可以委托给可重用的过滤器组件。
*   **性能考量 (Performance):** 目标选择可能涉及遍历游戏状态中的多个集合，需要考虑效率，避免不必要的计算和对象分配。对于频繁的选择模式可以考虑优化。
*   **可组合性 (Composability):** 允许将简单的选择器和过滤器组合起来，构建更复杂的选择逻辑。
*   **明确性 (Explicitness):** 配置应尽可能清晰地表达选择意图，避免歧义。
*   **玩家交互处理 (Player Interaction Handling):** 系统需要能区分自动选择和需要玩家手动选择的情况，并能与 UI 系统交互以获取玩家输入。

## 3. 数据结构定义

### 3.1 ITargetSelector 接口

### 3.1 ITargetSelector 接口

这是目标选择器逻辑的核心接口。它定义了一个方法，该方法接收目标选择上下文并返回选定目标的标识符集合。

```csharp
using System.Collections.Generic;

/// <summary>
/// 定义目标选择器的接口。
/// </summary>
public interface ITargetSelector
{
    /// <summary>
    /// 根据提供的上下文选择目标。
    /// </summary>
    /// <param name="context">目标选择所需的上下文信息。</param>
    /// <returns>选定目标的标识符集合。如果无法选择任何目标，则返回空集合。</returns>
    IEnumerable<TargetId> SelectTargets(TargetSelectionContext context);

    /// <summary>
    /// (可选考虑) 指示此选择器是否需要玩家手动选择。
    /// 如果为 true，则系统需要与 UI 交互以获取玩家输入。
    /// 另一种方式是由选择器的具体类型或配置决定是否需要交互。
    /// </summary>
    // bool RequiresPlayerSelection { get; }
}
```
*注：`RequiresPlayerSelection` 属性暂时注释掉，因为一个选择器配置可能同时包含自动部分和玩家选择部分，或者完全由配置驱动决定是否需要交互，放在接口层级可能过于僵化。*

### 3.2 TargetSelectionContext

此类封装了执行目标选择时所需的所有环境信息。它与 `ConditionContext` 类似，但可能包含一些特有的信息。

```csharp
using System; // 需要 using System;

/// <summary>
/// 目标选择操作的上下文信息。
/// </summary>
public class TargetSelectionContext
{
    /// <summary>
    /// 当前的游戏状态，提供对场面、玩家、牌库等的访问。
    /// </summary>
    public GameState CurrentGameState { get; }

    /// <summary>
    /// 触发此目标选择的能力来源卡牌实例。
    /// </summary>
    public CardInstance SourceCard { get; }

    /// <summary>
    /// 触发此能力链的原始游戏事件 (可能为 null)。
    /// 对于需要参照触发事件信息（如“刚刚被破坏的卡牌”）的选择器很有用。
    /// </summary>
    public IGameEvent? TriggeringEvent { get; }

    /// <summary>
    /// 与当前能力实例相关的变量集合 (可能为 null)。
    /// </summary>
    public AbilityVariables? AbilityVariables { get; }

    /// <summary>
    /// 控制来源卡牌的玩家控制器引用。
    /// </summary>
    public PlayerController SourcePlayerController { get; } // 假设已有 PlayerController 类

    // 可以根据需要添加其他辅助属性或方法，例如：
    // public PlayerController OpponentPlayerController => CurrentGameState.GetOpponentController(SourcePlayerController.PlayerId);
    // public PlayerState SourcePlayerState => CurrentGameState.GetPlayerState(SourcePlayerController.PlayerId);
    // public PlayerState OpponentPlayerState => CurrentGameState.GetPlayerState(OpponentPlayerController.PlayerId);

    public TargetSelectionContext(GameState gameState, CardInstance sourceCard, PlayerController sourcePlayerController, IGameEvent? triggeringEvent = null, AbilityVariables? abilityVariables = null)
    {
        CurrentGameState = gameState ?? throw new ArgumentNullException(nameof(gameState));
        SourceCard = sourceCard ?? throw new ArgumentNullException(nameof(sourceCard));
        SourcePlayerController = sourcePlayerController ?? throw new ArgumentNullException(nameof(sourcePlayerController));
        TriggeringEvent = triggeringEvent;
        AbilityVariables = abilityVariables;
    }
}
```

### 3.3 目标实体标识 (TargetId)

为了表示能力的目标，我们定义一个 `TargetId` 结构。由于所有目标（包括主战者）现在都统一表示为 `CardInstance`，`TargetId` 只需要存储卡牌实例的 ID。

```csharp
using System;
using System.Collections.Generic;

/// <summary>
/// 表示一个可被能力选定的目标的唯一标识符，即卡牌实例的 ID。
/// 使用 struct 以提高性能并减少内存分配。
/// </summary>
public readonly struct TargetId : IEquatable<TargetId>
{
    /// <summary>
    /// 目标的具体 ID，对应 CardInstance.InstanceId。
    /// </summary>
    public int Id { get; } // 使用 int 简化。如果 InstanceId 是 Guid 或其他类型，则需要调整。

    public TargetId(int instanceId)
    {
         if (instanceId <= 0) throw new ArgumentOutOfRangeException(nameof(instanceId), "Card Instance ID must be positive."); // 假设 InstanceId > 0
        Id = instanceId;
    }

    // 实现 IEquatable<TargetId> 和重写 Equals, GetHashCode
    public bool Equals(TargetId other) => Id == other.Id;
    public override bool Equals(object? obj) => obj is TargetId other && Equals(other);
    public override int GetHashCode() => Id.GetHashCode();

    public static bool operator ==(TargetId left, TargetId right) => left.Equals(right);
    public static bool operator !=(TargetId left, TargetId right) => !left.Equals(right);

    public override string ToString() => $"CardInstance:{Id}";

    // --- 静态工厂方法 ---
    /// <summary>
    /// 创建一个指向特定卡牌实例的目标 ID。
    /// </summary>
    public static TargetId Card(int instanceId)
    {
        return new TargetId(instanceId);
    }
}

// TargetType 枚举不再需要，因为所有目标都是 CardInstance。
// 如果未来需要区分非卡牌实例的目标（例如特殊的游戏区域或计数器），可以重新引入 TargetType。
```

## 4. JSON 配置结构

目标选择器的配置采用 JSON 格式，旨在提供足够的灵活性来描述各种选择场景。一个基本的目标选择器配置对象可能包含以下字段：

```json
{
  "selectorType": "Filtered", // 必需：选择器的主要类型 (见下文)
  "description": "选择一个敌方场上攻击力最高的随从", // 可选：对选择器的描述，便于理解
  "targetPool": { // 必需：定义初始目标池
    "source": "OpponentField", // 必需：目标来源区域/类型 (见下文)
    // "entityType" 字段已移除，所有目标都是 CardInstance
    // "cardType" 字段已移除，类型过滤应通过 filters 或 DSL 实现
  },
  "filters": [ // 可选：用于进一步筛选目标池的过滤器数组
    {
      "filterType": "PropertyComparison", // 过滤器类型
      "property": "Attack", // 要比较的属性
      "comparison": "Equals", // 比较操作
      "valueSource": { // 值的来源
         "type": "Max", // 取目标池中指定属性的最大值
         "property": "Attack",
         "fromPool": "SameAsTargetPool" // 指定从哪个池计算最大值
      }
    }
    // 可以添加更多过滤器，例如：
    // { "filterType": "HasTrait", "trait": "Commander" },
    // { "filterType": "Condition", "conditionDsl": "Target.Cost <= Context.SourceCard.Cost" } // 复用条件系统DSL
  ],
  "count": { // 必需：定义选择目标的数量
    "mode": "Exact", // 数量模式 (Exact, Max, Range, All)
    "value": 1
    // 对于 Range: "minValue": 1, "maxValue": 3
    // 对于 Max: "value": 5 (最多选5个)
  },
  "ordering": { // 可选：在选择前对过滤后的目标进行排序
     "property": "Cost", // 排序依据的属性
     "direction": "Ascending" // 排序方向 (Ascending, Descending, Random)
     // 可以有多个排序条件
     // "thenBy": { "property": "Attack", "direction": "Descending" }
  },
  "playerChoice": { // 可选：定义玩家交互
    "isRequired": false, // 是否强制需要玩家选择 (如果为 true, 即使过滤后只剩一个也要玩家确认)
    "prompt": "请选择一个目标随从", // 可选：给玩家的提示信息
    "canCancel": false // 可选：玩家是否可以取消选择 (如果取消，能力可能无法结算)
    // "autoSelectSingleIfPossible": true // 可选：如果过滤和排序后只剩下一个符合数量要求的目标，是否自动选择
  },
  "onFailure": "AbortAbility" // 可选：如果无法选出足够数量的目标，应如何处理 (AbortAbility, SkipEffect, LogWarning)
}
```

### 4.1 主要字段说明

*   **`selectorType`**: 标识选择器的基本行为模式。常见的类型可能包括：
    *   `Self`: 选择能力来源卡牌自身 (`CardInstance`)。
    *   `Filtered`: 最通用的类型，通过 `targetPool` 和 `filters` 定义选择逻辑。
    *   `FromVariable`: 从 `AbilityVariables` 中获取目标列表 (`TargetId` 列表)。
    *   `TriggeringEventData`: 从触发事件的数据中提取目标 (例如 "造成伤害的目标", "被破坏的卡牌")。返回 `TargetId` 列表。
    *   `Composite`: 组合多个子选择器结果 (例如 "选择一个己方随从和所有敌方随从")。
    *   `PlayerChoice`: 明确要求玩家从指定的池中选择，可能带有预过滤。
*   **`targetPool.source`**: 定义目标的初始来源或类型。枚举值可能包括：
    *   `OwnField`, `OpponentField`: 己方/敌方战场。
    *   `OwnHand`, `OpponentHand`: 己方/敌方手牌。
    *   `OwnDeck`, `OpponentDeck`: 己方/敌方牌库。
    *   `OwnGraveyard`, `OpponentGraveyard`: 己方/敌方墓地。
    *   `OwnLeader`, `OpponentLeader`: 指向代表己方/敌方主战者的特殊 `CardInstance`。
    *   `AllCardsInPlay`: 双方战场所有卡牌。
    *   `AllCards`: 游戏中所有区域的卡牌 (慎用，性能影响大)。
    *   `TriggeringEventTargets`: 触发事件直接关联的目标 (`CardInstance` 列表)。
    *   `ContextSourceCard`: 能力来源卡牌自身 (`CardInstance`)。
    *   `DslQuery`: 使用自定义 DSL 查询 `CardInstance`。需要配合 `queryDsl` 字段。
*   **`targetPool.queryDsl`**: (仅当 `source` 为 `DslQuery` 时使用) 包含目标选择的 DSL 查询字符串。DSL 的设计需要另行文档化，但应能支持类似 SQL 或 LINQ 的查询，例如 `All().In(OwnField).Where(c => c.CardType == 'Follower' && c.Attack > c.BaseAttack)`。
*   **`filters`**: 一个过滤器对象数组。每个过滤器对象应包含 `filterType` 及该类型所需的参数。过滤器作用于从 `targetPool` 获取的 `CardInstance` 集合。常见的 `filterType` 可能有：
    *   `PropertyComparison`: 比较目标的某个属性与特定值或上下文中的值。
    *   `HasTrait`: 检查目标是否具有特定特性。
    *   `Condition`: 使用条件系统 (DSL/AST/JSON) 进行复杂判断。
    *   `IsSpecificCard`: 检查是否是某个具体的卡牌 (通过 CardId)。
    *   `RelativePosition`: (例如 "相邻的随从")。
*   **`count.mode`**:
    *   `Exact`: 必须选择精确数量的目标。
    *   `Max`: 最多选择指定数量的目标。
    *   `Range`: 选择数量在指定范围内的目标。
    *   `All`: 选择所有符合条件的目标。
*   **`ordering`**: 定义排序规则，用于从多个符合条件的目标中按优先级选择，或呈现给玩家选择。
*   **`playerChoice`**: 控制玩家交互的细节。`isRequired` 决定是否必须由玩家操作。
*   **`onFailure`**: 定义当无法按要求选出目标时的备选行为。

### 4.2 嵌套与组合

对于复杂选择逻辑（例如“选择一个己方随从A，然后选择一个费用小于A的敌方随从B”），可以通过以下方式实现：

1.  **`Composite` 选择器类型**: 允许组合多个子选择器的结果。
2.  **过滤器引用上下文**: 在过滤器的值来源 (`valueSource`) 中引用之前步骤选定的目标或上下文信息。
3.  **效果链**: 将复杂选择分解为能力效果链中的多个步骤，每个步骤执行一次选择和效果。

具体选择哪种方式取决于实现的复杂度和配置的易用性权衡。初期建议优先支持简单的 `Filtered` 类型，逐步扩展。

## 6. 与系统其他部分交互

目标选择系统不是孤立的，它需要与游戏引擎的其他核心部分紧密协作：

*   **条件系统 (Condition System):**
    *   **输入:** 目标选择器中的 `Condition` 过滤器会调用条件系统来评估特定目标是否满足复杂条件。
    *   **输出:** 条件系统返回布尔结果，供过滤器使用。
    *   **依赖:** 目标选择器需要能解析和执行条件配置 (DSL/JSON/AST)。

*   **效果执行器 (Effect Executor):**
    *   **输入:** 目标选择系统将最终选定的 `TargetId` 列表传递给效果执行器。
    *   **输出:** 无直接输出给目标选择系统，但效果执行器会根据目标修改游戏状态。
    *   **流程:** 能力触发 -> 条件检查 -> **目标选择** -> 效果执行。

*   **游戏状态 (GameState):**
    *   **输入:** 目标选择系统需要读取 `GameState` 来获取目标池（如战场卡牌、手牌、玩家状态等）以及计算目标属性。
    *   **输出:** 无直接输出，但选择过程本身不应修改 `GameState`（只读）。

*   **事件系统 (Event System):**
    *   **输入:**
        *   某些选择器 (`TriggeringEventData`) 需要从触发能力的 `IGameEvent` 中提取信息（如事件的目标）。
        *   目标选择过程本身，特别是需要玩家选择时，可能会触发 UI 事件或等待 UI 事件。
    *   **输出:**
        *   目标选择完成（成功或失败）可以作为一个事件广播出去，供其他系统（如日志、AI）监听。
        *   如果需要玩家选择，会向 UI 系统发出请求事件。

*   **UI 系统 (User Interface):**
    *   **输入:** 当 `playerChoice.isRequired` 为 `true` 或系统无法自动确定唯一目标时，目标选择系统需要向 UI 发送请求，展示可选目标列表和提示信息 (`playerChoice.prompt`)。
    *   **输出:** UI 系统将玩家选择的 `TargetId` 或取消操作的结果返回给目标选择系统。
    *   **交互:** 这是系统中最复杂的交互之一，需要定义清晰的请求/响应协议。

### 交互流程示例 (Mermaid Sequence Diagram)

```mermaid
sequenceDiagram
    participant Ability as 卡牌能力实例
    participant ConditionSys as 条件系统
    participant TargetSelector as 目标选择器
    participant GameState as 游戏状态
    participant EffectExecutor as 效果执行器
    participant EventSys as 事件系统
    participant UI as 用户界面

    Ability->>ConditionSys: CheckConditions(context)
    ConditionSys->>GameState: 读取状态/属性
    GameState-->>ConditionSys: 返回状态/属性
    ConditionSys-->>Ability: 条件满足 (true)

    Ability->>TargetSelector: SelectTargets(context)
    TargetSelector->>GameState: 获取目标池 (e.g., OpponentField)
    GameState-->>TargetSelector: 返回初始目标列表
    TargetSelector->>TargetSelector: 应用过滤器 (Filters)
    loop 对每个目标应用过滤器
        opt 使用条件过滤器
            TargetSelector->>ConditionSys: EvaluateCondition(target, filterCondition, context)
            ConditionSys->>GameState: 读取目标属性
            GameState-->>ConditionSys: 返回属性
            ConditionSys-->>TargetSelector: 过滤器结果 (true/false)
        end
    end
    TargetSelector->>TargetSelector: 应用排序 (Ordering)
    TargetSelector->>TargetSelector: 应用数量限制 (Count)

    alt 需要玩家选择 (e.g., count.mode != All, playerChoice.isRequired=true)
        TargetSelector->>EventSys: 触发 PlayerChoiceRequired 事件 (可选目标列表, prompt)
        EventSys->>UI: 显示选择界面 (可选目标, prompt)
        UI->>User: 请求选择
        User->>UI: 选择目标 / 取消
        UI->>EventSys: 触发 PlayerChoiceMade 事件 (selectedTargets / cancelled)
        EventSys->>TargetSelector: 返回玩家选择结果
    else 自动选择
        TargetSelector->>TargetSelector: 自动确定最终目标
    end

    alt 选择成功
        TargetSelector-->>Ability: 返回选定目标列表 (selectedTargets)
        Ability->>EffectExecutor: ExecuteEffects(selectedTargets, context)
        EffectExecutor->>GameState: 修改状态 (应用效果)
        EffectExecutor->>EventSys: 触发效果结算事件
    else 选择失败 (e.g., 数量不足, 玩家取消)
        TargetSelector-->>Ability: 返回空列表 / 失败状态
        opt onFailure == AbortAbility
             Ability->>Ability: 中止能力结算
        else opt onFailure == SkipEffect
             Ability->>Ability: 跳过效果执行，继续后续步骤 (如果有)
        else // 默认为 LogWarning 或其他处理
             Ability->>Ability: 记录警告，继续后续步骤 (如果有)
        end
    end
```
