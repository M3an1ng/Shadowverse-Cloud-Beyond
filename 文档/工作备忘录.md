**状态:** 进行中

- **原因诊断:** 这表明 Vite 代理尝试连接配置的后端目标地址 (`https://localhost:7097`) 时，连接被**拒绝**了。这通常意味着：

- 此 `ECONNREFUSED` 错误发生在尝试与后端建立连接时，比之前的 `500 Internal Server Error` (表示连接已建立但处理出错) 更早阶段。

**下一步:**

- **首要:** 请用户**确认 C# 后端 API 服务器 (`ShadowverseBeyond.Server`) 是否正在运行**，并检查它实际监听的 URL 和端口 (应与 `launchSettings.json` 配置一致，通常是 `https://localhost:7097`)。

**日期:** 2025-05-27
**任务:** Bug Fix - 前端玩家状态显示 '?'
**状态:** <span style="color:green">**已解决**</span>
**问题描述:**

- 游戏界面中，本地和对手玩家的生命值 (Health)、PP、EP 显示为 '?' 而非实际数值。

**原因诊断:**

- 通过在 `src/gameManager.js` 的 `updateFullGameState` 函数中添加 `console.log` 调试，发现从服务器接收到的 `PlayerStateDto` 对象中，相关属性名为 `leaderHealth`, `currentPP`, `currentEP`。
- 前端 UI 渲染逻辑 (`src/ui.js`) 预期接收的属性名为 `health`, `pp`, `ep`。
- 属性名不匹配导致 UI 无法正确读取和显示数值。

**解决方案:**

- 在 `src/gameManager.js` 的 `updateFullGameState` 函数内部，在接收并合并服务器状态后，添加了 **映射逻辑**。
- 此逻辑遍历 `gameState.players` 数组，为每个玩家对象创建新的 `health`, `pp`, `ep` 属性，并将服务器 DTO 中的 `leaderHealth`, `currentPP`, `currentEP` 的值分别赋给它们。
- `代码片段 (src/gameManager.js - updateFullGameState 内):`
  ```javascript
  // --- Add Mapping Logic START ---
  // Map server DTO names (leaderHealth, currentPP, currentEP) to UI expected names (health, pp, ep)
  gameState.players.forEach((player) => {
    if (player) {
      player.health = player.leaderHealth; // Map leaderHealth to health
      player.pp = player.currentPP; // Map currentPP to pp
      player.ep = player.currentEP; // Map currentEP to ep
    }
  });
  // --- Add Mapping Logic END ---
  ```

**测试验证 (SOP 4a/4b):**

- 用户重新构建并运行应用。
- **结果:** 用户确认玩家状态数值 (Health, PP, EP) **正常显示**。

**后续清理:**

- 确认修复有效后，移除了 `src/gameManager.js` 中添加的临时 `console.log` 调试语句。
