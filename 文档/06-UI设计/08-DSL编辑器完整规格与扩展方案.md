# 08. DSL编辑器完整规格与扩展方案 (V1.0)

**版本: 1.0**

**作者: AI 技术总监**

**更新日期: 2025-12-21**

## 1. 背景与目标

本文件在 `05-DSL编辑器架构与工作流程指南.md` 与 `07-DSL编辑器交互流程设计.md` 的基础上，补齐实现细节与扩展路线，形成**可直接落地的完整规格**。目标包括：

- 支持**逐层编辑**、**封装**与**逻辑解析**的可视化 DSL 构建体验。
- 在完整表达式区域以**层层胶囊**形式展示，并允许点击任意层进行编辑。
- 对每一层表达式进行类型检测，以 **√/×** 状态提示。
- 支持**中文可读化展示**，避免普通玩家直接面对 DSL 语法。
- 增强“用户收藏”与“表达式反向解析”能力。

## 2. 范围与非目标

### 2.1. 范围

- DslEditor 的交互流程、状态模型、UI 结构与视觉反馈规范。
- 类型检测与胶囊状态的判定策略。
- 中文化展示策略（字段/函数/运算符）。
- 收藏与反向解析的技术落地路线与接口约定。

### 2.2. 非目标

- 游戏玩法规则或 DSL 语义的扩展设计。
- 运行时 DSL 执行性能优化（由后端 DSL 执行器负责）。

## 3. 关键术语

- **虚拟根 (Virtual Root)**: 仅有 `main` 槽位的顶层容器。
- **编辑路径 (Editing Path)**: 记录“工作区正在编辑哪个槽位”的栈。
- **工作区 (Workspace)**: 当前编辑的 AST 片段。
- **封装表达式 (Encapsulated)**: 将子表达式封装为可嵌套的胶囊。
- **占位符 (Placeholder)**: 封装空表达式 `( )`，提示待编辑输入。

## 4. 核心架构与状态模型

### 4.1. 统一状态模型

- 所有编辑操作统一为“**编辑某个 AST 节点的某个槽位**”。
- 主表达式 = `virtualRoot.main`，与其他节点槽位编辑保持一致。

### 4.2. 核心状态字段（前端）

- `virtualRoot.main`: 主表达式（封装节点）。
- `workspaceAST / astRoot`: 当前编辑片段。
- `editingPath`: 当前编辑上下文栈。
- `expectedType / slotExpectedType`: 类型期望（根/槽位）。

## 5. UI 分区与视觉规范

### 5.1. 主表达式区域

- 展示由**封装胶囊**组成的完整表达式。
- 点击任意胶囊进入子表达式编辑。
- 胶囊样式：
  - 绿色：类型匹配（√）
  - 红色：类型不匹配（×）

### 5.2. 工作区区域

- 显示当前片段 AST。
- 提供 `[+]` 新增、`[×]` 清空、`[−]` 返回、`[✓]` 保存等操作。
- 在顶部提示“当前槽位期望类型”。

### 5.4. CardQuery Pipeline Editor

- 当当前编辑片段为集合链式查询（`.query/.orderBy/.take`）时，展示 Pipeline 编辑面板。
- Pipeline 以“阶段列表”方式呈现，支持添加、移除、拖拽排序。
- 阶段与 DSL 对应关系：
  - Filter → `.query(...)`
  - Sort → `.orderBy(...)`
  - Select → `.take(...)`（当前仅支持“取前/First”）
- 解析失败的链式表达式以“原始阶段”展示，仅只读，保证信息不丢失。

### 5.3. 可读化预览

- 显示中文表达式（非 DSL 语法）。
- 运算符、字段、函数均应映射为中文描述。

## 6. 交互流程

### 6.1. 新建表达式

1. 初始化时 `virtualRoot.main = ( )`。
2. 工作区进入 `main` 槽位编辑。
3. 选择数据源/值后保存封装，形成第一个胶囊。

### 6.2. 左半表达式封装 → 右侧占位

1. 在已有胶囊上选择操作符（例如 `>`）。
2. 自动把左侧封装写回主表达式。
3. 右侧生成占位胶囊 `( )` 并进入编辑。

### 6.3. 编辑任意子表达式

1. 点击主表达式中的目标胶囊。
2. 对应子表达式载入工作区。
3. 保存后写回其父节点槽位。

## 7. 类型检测与胶囊状态

### 7.1. 期望类型来源

- `expectedType`: 来自外层 DSL 输入框的返回类型要求。
- `slotExpectedType`: 由父节点槽位决定（如函数参数、筛选表达式）。

### 7.2. 判定逻辑

- 每一层胶囊根据“当前层表达式的实际类型”对比“该层期望类型”。
- 最终只在**步骤跳转/保存时**阻断类型错误。

### 7.3. 胶囊状态

- √: 类型匹配
- ×: 类型不匹配（悬浮提示详细原因）

## 8. 中文可读化与节点展示

### 8.1. 中文化原则

- UI 只展示中文友好描述，DSL 语法仅作为可选调试信息。
- 字段名、函数名、上下文对象使用元数据的 `displayName`。
- 运算符使用语义化翻译（如 `&&` → “且”）。

### 8.2. 可读化输出逻辑

- `toReadableText` 应优先使用 `displayName` 或 `displayValue`。
- 属性链应显示为 `对象名.字段名` 的中文链式描述。

## 9. 现状实现与差距

### 9.1. 与预期一致的部分

- 虚拟根 + 编辑路径模型已实现。
- 支持逐层封装与右侧占位符流程。
- 胶囊 √/× 提示已存在。
- 可读化预览已提供框架。
- 单实例内的“单工作区”模式已实现：同一 DslEditor 只有一个工作区，根据编辑路径载入不同片段。

### 9.2. 存在差距与遗漏

1. **单例工作区（澄清）**  
   单例工作区指“每个 DslEditor 只有一个工作区”，根据编辑路径载入不同片段。该模式已满足；若未来要改成“全页面唯一工作区”，需要单独新增规范与重构方案。

2. **“点击任意部分编辑”不足**  
   当前主要依赖“封装胶囊”作为可点击入口，非封装节点无法直接点击编辑。

3. **中文显示不完整**  
   字段与属性链目前显示 DSL 原文，未统一使用 `displayName`。

4. **反向解析能力不足**  
   前端 `parseExpression` 仅支持字面量、属性链、query/orderBy/take，复杂表达式仍以 `rawText` 形式存在。

## 10. 扩展方案：用户收藏

### 10.1. 目标

- 用户可收藏高频 DSL，并在编辑时快速插入。

### 10.2. 数据模型

建议新增 `AbilityDslFavorites` 表或等价存储：

- `id`
- `userId`
- `label`
- `expression`
- `expectedType`
- `tags`
- `usageCount`
- `lastUsedAt`

### 10.3. API 设计

- `GET /api/dsl-favorites?query=&expectedType=&limit=`
- `POST /api/dsl-favorites`
- `DELETE /api/dsl-favorites/{id}`
- `PUT /api/dsl-favorites/{id}`（改名/更新标签）
- `POST /api/dsl-favorites/{id}/use`（使用计数）

### 10.4. 前端交互

- DslEditor 选项面板新增「收藏 / 最近使用」分区。
- 收藏条目可直接插入当前工作区。
- 当前表达式可“一键收藏”。

## 11. 扩展方案：表达式反向解析

### 11.1. 目标

将已有 DSL 还原为可编辑 AST，以支持“复制/收藏/加载”后完整可视化编辑。

### 11.2. 方案 A：前端解析器

- 将后端 DSL 语法移植为 JS Parser。
- 优点：纯前端，响应快。
- 代价：维护成本高。

### 11.3. 方案 B：后端解析服务

- 新增 `POST /api/dsl/parse`，返回 AST JSON。
- 前端将 AST JSON 转换为 UI AST。
- 优点：语法一致性高。

### 11.4. 兼容策略

即使解析失败，也可保留 `rawText` 节点显示，并允许在工作区重写。

## 12. 落地里程碑与验收

### 12.1. 里程碑

1. 中文显示与胶囊点击体验增强
2. 收藏功能落地
3. 反向解析能力落地

### 12.2. 验收标准

- 任意层表达式均能进入编辑态。
- 胶囊类型校验准确展示 √/×。
- 中文可读化展示完整且一致。
- 收藏表达式可快速插入并保持类型约束。
- 复杂 DSL 可被完整还原为可视化表达。
