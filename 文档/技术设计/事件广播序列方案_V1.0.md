# 事件广播序列方案 V1.0

**关联任务:** M8: 事件广播机制重构

**日期:** 2025-05-31

**作者:** @Roo

## 1. 目标

-   **根本解决事件时序问题:** 确保客户端接收到的游戏事件顺序与服务器端逻辑执行顺序严格一致，避免因并发或异步处理导致的乱序。
-   **提升事件原子性:** 将一个完整玩家操作（如出牌、攻击）或一个完整 AI 回合产生的所有相关事件作为一个整体进行广播，使客户端能够更连贯地处理和展示游戏过程。
-   **简化服务层逻辑:** 将事件收集的职责上移，使核心服务方法（如 `GameService` 中的方法）专注于状态变更，而不是事件广播。
-   **提高可测试性:** 使服务层方法的单元测试更简单，只需验证状态变更和返回的事件列表，无需 Mock SignalR Hub。

## 2. 核心概念

### 2.1 GameActionContext

-   **定义:** 一个简单的类，用于在单个逻辑操作（玩家请求或 AI 回合）的范围内收集产生的游戏事件。
-   **结构:**
    ```csharp
    // Server/Models/GameActionContext.cs
    public class GameActionContext
    {
        public List<GameEventDto> Events { get; } = new List<GameEventDto>();
        // 未来可能添加其他上下文信息，如操作发起者 ID 等
    }
    ```
-   **作用:**
    -   作为参数在服务调用链中传递。
    -   所有产生事件的服务方法不再直接广播，而是将事件 DTO 添加到传入的 `GameActionContext.Events` 列表中。

### 2.2 事件收集与广播边界

-   **边界定义:** 一个完整的用户操作（通过 `GameHub` 接收）或一个完整的 AI 回合（通过 `AiTurnExecutor` 或类似机制触发）构成一个事件收集与广播的边界。
-   **流程:**
    1.  在操作入口处（`GameHub` 方法或 AI 回合启动点）创建 `GameActionContext` 实例。
    2.  将此 context 实例传递给后续调用的服务方法 (`GameService`, `AiTurnExecutor` 等)。
    3.  服务方法内部执行逻辑，修改游戏状态，并将产生的事件 DTO 添加到 context 的 `Events` 列表中。
    4.  当操作执行完毕，回到入口点时，从 context 中获取完整的 `Events` 列表。
    5.  在入口点统一调用 `BroadcastEventsAsync` (或类似方法) 将收集到的所有事件按顺序广播给客户端。

## 3. 实现方案

### 3.1 `GameActionContext` 类定义

-   已在 `Server/Models/GameActionContext.cs` 中实现 (M8 Step 1)。

### 3.2 `IGameService` 接口修改

-   将 `GameActionContext` 参数添加到需要收集事件的服务方法签名中。
-   例如：
    ```csharp
    // 修改前
    Task<IEnumerable<GameEventDto>> EndTurnAsync(string gameId, string playerId);
    // 修改后
    Task EndTurnAsync(string gameId, string playerId, GameActionContext context); // 返回值移除，事件通过 context 收集
    ```
-   已在 `Server/Services/IGameService.cs` 中部分实现 (M8 Step 2)。

### 3.3 `GameService` 实现修改

-   修改实现了 `IGameService` 的方法：
    -   接收 `GameActionContext` 参数。
    -   在方法内部，当产生游戏事件时，创建对应的 `GameEventDto` 并添加到 `context.Events.Add()`。
    -   移除方法内部原有的 `_hubContext.Clients...SendAsync(...)` 或 `BroadcastEventAsync` 调用。
    -   调整方法返回值（通常不再需要返回 `IEnumerable<GameEventDto>`）。
-   已在 `Server/Services/GameService.cs` 中部分实现 (M8 Step 3)。

### 3.4 `GameHub` 修改

-   在处理玩家动作的 Hub 方法 (如 `PerformEndTurn`, `PerformPlayCard` 等) 的开头创建 `GameActionContext` 实例。
    ```csharp
    public async Task PerformEndTurn()
    {
        var playerId = Context.UserIdentifier;
        var gameId = await _gameManager.GetPlayerGameIdAsync(playerId);
        if (gameId == null) { /* handle error */ return; }

        var context = new GameActionContext(); // 创建 Context
        try
        {
            await _gameService.EndTurnAsync(gameId, playerId, context); // 传递 Context
            await BroadcastEventsAsync(gameId, context.Events); // 统一广播
        }
        catch (Exception ex)
        {
            // 处理异常，可能需要广播错误事件
            _logger.LogError(ex, "Error ending turn for player {PlayerId} in game {GameId}", playerId, gameId);
            await Clients.Caller.ReceiveError("Error ending turn: " + ex.Message);
        }
    }
    ```
-   在调用 `_gameService` 方法后，从 context 获取 `Events` 列表。
-   调用 `BroadcastEventsAsync` (或直接使用 `_hubContext`) 将收集到的事件列表广播给游戏中的所有客户端。
-   **状态:** 待实现 (M8 后续步骤)。

### 3.5 `AiTurnExecutor` 修改

-   修改 `ExecuteTurnAsync` 方法签名，接收 `GameActionContext` 参数。
-   将接收到的 context 传递给其内部调用的 `_gameService` 方法。
-   **状态:** 已完成 (M8 Step 4)。

### 3.6 AI 回合调用者修改

-   负责触发 AI 回合的方法 (当前是 `GameService.ExecuteAiActionPhaseAsync`) 需要：
    -   在调用 `AiTurnExecutor.ExecuteTurnAsync` 之前创建 `GameActionContext` 实例。
    -   将 context 传递给 `ExecuteTurnAsync`。
    -   在 `ExecuteTurnAsync` 调用完成后，从 context 获取 `Events` 列表。
    -   调用 `BroadcastEventsAsync` 统一广播 AI 回合产生的所有事件。
-   **状态:** 已完成 (M8 Step 6)。
    ```csharp
    // Server/Services/GameService.cs (ExecuteAiActionPhaseAsync)
    // ...
    var context = new GameActionContext(); // 创建 Context
    _logger.LogDebug("[AI_TURN:{GameId}:{PlayerId}] Created GameActionContext for AI turn.", gameId, aiPlayerId);
    await aiTurnExecutorInstance.ExecuteTurnAsync(gameId, aiPlayerId, context); // 传递 Context
    _logger.LogInformation("[AI_TURN:{GameId}:{PlayerId}] AiTurnExecutor completed. Broadcasting {EventCount} collected events.", gameId, aiPlayerId, context.Events.Count);
    await BroadcastEventsAsync(gameId, context.Events); // 统一广播
    // ...
    ```

## 4. 事件广播流程 (示例: 玩家结束回合)

1.  **Client:** 用户点击 "结束回合" 按钮。
2.  **Client (JS):** `signalRConnection.invoke("PerformEndTurn")`。
3.  **Server (GameHub):** `PerformEndTurn()` 方法被调用。
4.  **Server (GameHub):** `var context = new GameActionContext();` 创建上下文。
5.  **Server (GameHub):** 调用 `await _gameService.EndTurnAsync(gameId, playerId, context);`。
6.  **Server (GameService):** `EndTurnAsync` 执行：
    -   验证回合结束合法性。
    -   触发回合结束效果 (如果实现)。
    -   修改 `GameState` (切换 `currentPlayerId` 等)。
    -   `context.Events.Add(new TurnEndedEventDto(...));`
    -   `context.Events.Add(new NextTurnStartedEventDto(...));` (假设新回合开始事件也在此处生成)
    -   `context.Events.Add(new ResourceUpdatedEventDto(...));`
    -   `context.Events.Add(new CardDrawnEventDto(...));`
    -   ... (所有相关事件都被添加到 context)
    -   方法执行完毕，返回到 `GameHub`。
7.  **Server (GameHub):** 从 `context.Events` 获取包含多个事件的列表。
8.  **Server (GameHub):** 调用 `await BroadcastEventsAsync(gameId, context.Events);`。
9.  **Server (Broadcast):** 遍历事件列表，按顺序 `SendAsync` 给 `Clients.Group(gameId)`。
10. **Client (JS):** `signalRConnection.on("ReceiveGameEvents", (events) => { ... });` 接收到包含多个事件的数组。
11. **Client (JS):** 遍历事件数组，按顺序处理并更新 UI。

## 5. 优点

-   **保证事件顺序:** 从根本上解决了异步广播可能导致的乱序问题。
-   **操作原子性:** 一个逻辑操作产生的所有事件作为一个整体广播，便于客户端理解和处理。
-   **简化服务逻辑:** `GameService` 等核心服务更专注于业务逻辑和状态变更。
-   **提高可测试性:** 单元测试只需验证状态和返回的事件列表。
-   **减少 SignalR 调用:** 将多次单独广播合并为一次或少数几次批量广播，可能略微降低网络开销。

## 6. 潜在问题/考虑

-   **Context 传递:** 需要确保 context 在整个调用链中正确传递，遗漏可能导致事件丢失。
-   **错误处理:** 如果在操作中途发生异常，需要决定如何处理已收集的事件 (是丢弃还是广播部分事件，或者广播一个错误事件)。当前倾向于在 Hub 层捕获异常，不广播部分事件，而是发送特定的错误消息给调用者。
-   **大型操作:** 对于可能产生大量事件的操作 (如复杂的 AOE 法术)，一次性收集和广播大量事件可能对内存和网络有一定压力，但对于卡牌游戏通常可接受。
