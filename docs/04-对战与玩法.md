# 对战与玩法

> 核对日期：2026-09-27。本文列出代码中的默认规则和关键边界，不替代各模式的运行时配置与测试。

## 房间与单局

- `RoomId` 标识房间；`ActiveGameId` 标识该房间当前对局。房间和对局不是同一生命周期。
- 房间创建、加入、准备、开局、切换牌组、离开与列表入口在 [MatchController](../Server/Controllers/MatchController.cs)。
- [MatchService](../Server/Services/MatchService.cs) 负责房间和单局映射；[MatchRoom](../Server/Domain/Entities/MatchRoom.cs) 保存房间相关状态。
- 对局 Hub 连接优先使用 `roomId`，仍处理旧 `gameId` 输入。控制器也保留部分房间语义的旧 `GameId` 输出兼容。新增代码应明确区分两种 ID。
- 对局结算、回放和统计应核对单局身份，不拿房间 ID 直接替代。

玩家连接与观战走不同分支；`playerId`、连接令牌、加入码等校验见 [GameHub](../Server/Hubs/GameHub.cs)。前端连接组装见 [gameManager.js](../src/gameManager.js)。不要把对局连接令牌解释为账号 JWT。

## 默认规则常量

来源：[GameConstants](../Server/Domain/Constants/GameConstants.cs)。这些是默认值，不保证所有实验室或特殊模式都使用同一参数。

| 项目 | 默认值 |
|---|---|
| 场上单位上限 / 纹章上限 | 5 / 5 |
| 手牌上限 | 9 |
| 先手 / 后手初始手牌 | 4 / 4 |
| 主战者最大生命 | 20 |
| 常规 PP 上限 | 10 |
| 先手 / 后手进化点 | 2 / 2 |
| 先手 / 后手进化解锁回合 | 5 / 4 |
| 先手 / 后手超进化点 | 2 / 2 |
| 先手 / 后手超进化解锁回合 | 7 / 6 |
| 默认回合超时 | 180 秒 |
| 标准牌组数量 | 40 |
| 默认同名卡数量上限 | 3，实际还需检查环境限张策略 |

后手 PP+1 相关常量含每阶段一次、提升量 1、第 6 回合重置。费用、增幅和特殊打出方式由 [PlayModeResolver](../Server/Domain/Abilities/PlayModeResolver.cs) 与相关系统能力结算，别仅根据前端显示费用判断。

## 出牌、攻击和回合

阅读 [系统能力目录](../Server/Domain/Abilities/System/) 中的 `PlayCardAbility`、`AttackAbility`、`EvolveAbility`、`EndTurnAbility` 和 `MulliganAbility`，再沿事件与效果处理器追踪。

回合边界清理集中到 [TurnBoundaryCleanupService](../Server/Domain/GameFlow/TurnBoundaryCleanupService.cs)，与 [BuffService](../Server/Domain/Buffs/BuffService.cs) 协作收集过期事件。不要在 UI 切换、回合事件处理器和能力处理器中各自再加一套清理规则。

历史用例（已于 2026-10-23 归档，不作为当前回归证据）：[TurnBoundaryCleanupTests](../Server.Tests/Archive/2026-10-23-business/TurnBoundaryCleanupTests.cs)、[PpBoostPaymentModelTests](../Server.Tests/Archive/2026-10-23-business/PpBoostPaymentModelTests.cs)、[PlayModeResolverTests](../Server.Tests/Archive/2026-10-23-business/PlayModeResolverTests.cs)、[MulliganHandOrderTests](../Server.Tests/Archive/2026-10-23-business/MulliganHandOrderTests.cs)。文件存在不表示本次已运行这些测试。

## 牌组与环境

[DeckService](../Server/Services/DeckService.cs) 负责牌组操作，[DeckCodeService](../Server/Services/DeckCodeService.cs) 负责代码格式，[DeckValidationService](../Server/Services/DeckValidationService.cs) 负责规则校验。限张策略入口为 [DeckCopyLimitPoliciesController](../Server/Controllers/DeckCopyLimitPoliciesController.cs)。

游客牌组使用 [GuestDeckStore](../Server/Services/GuestDeckStore.cs)，账号牌组与游客迁移另有持久化流程。测试房间、不同环境、双职业等分支应阅读对应实现和 OpenSpec；不要把默认常量当作全部玩法规则。

## 活动、任务和金币

[QuestProgressService](../Server/Services/QuestProgressService.cs) 根据活动类型匹配任务，按周期和来源去重并更新完成状态；任务事件记录与奖励领取分开。奖励入口在 [EconomyService.Quests](../Server/Services/EconomyService.Quests.cs)，对局相关元进度在 [MetaProgressionService](../Server/Services/MetaProgressionService.cs)。

排查“任务完成但金币未变”时先核对是否领取、任务周期和去重记录，再查金币事务。观战活动另见 [SpectatorQuestProgressRecorder](../Server/Services/SpectatorQuestProgressRecorder.cs)，不要按加入房间就推断已计入任务。

## 聊天与表情

[EmoteCatalogOptions](../Server/Services/EmoteCatalogOptions.cs) 默认从 `assets/emotes` 读取表情目录，目录元数据缓存默认为 60 秒。[EmoteCatalogService](../Server/Services/EmoteCatalogService.cs) 处理资源目录，[GameHub](../Server/Hubs/GameHub.cs) 处理消息，[InMemoryGameChatService](../Server/Services/InMemoryGameChatService.cs) 保存近期聊天状态；前端通过 [emoteCatalog.js](../src/emoteCatalog.js) 加载目录。

本地展示偏好见 [battleCustomization.js](../src/battleCustomization.js)，与账号数据、房间状态和未来大厅定制分开。
