## 账号与身份边界

`POST /api/auth/register`、`POST /api/auth/login` 使用用户名和密码，密码校验通过 [Pbkdf2PasswordHasher](../Server/Services/Pbkdf2PasswordHasher.cs)。返回对象包含 `UserId`、`Username`、`AvatarUrl`、`Role`、`PermissionLevel` 及游客牌组迁移计数，没有旧文档所述的 Access Token / Refresh Token 字段。

[userSession.js](../src/userSession.js) 经存储适配保存用户 ID、昵称、角色等信息；业务接口中仍存在 `actorUserId` 参数、`X-Editor-UserId` 头等显式身份传递方式。对局 Hub 的连接令牌属于另一套连接上下文。不要把这些字段当作已经完成统一服务器会话认证的证据。

角色查表或前端隐藏按钮并不自动证明请求方身份可信。对公网开放前，应单独审查账号身份绑定、管理端点、日志端点和静态文件暴露范围。本次仅记录现状，未修改认证逻辑。

## SignalR

| Hub | 作用 | 主要入口 |
|---|---|---|
| `/gamehub` | 对局动作、状态、玩家选择、聊天和回放补流 | [GameHub](../Server/Hubs/GameHub.cs) |
| `/loghub` | 实时日志及日志快照 | [LogStreamHub](../Server/Hubs/LogStreamHub.cs) |

GameHub 对局方法包括 `PlayCard`、`PerformAttack`、`PerformEvolve`、`PerformSuperEvolve`、`PerformPpBoost`、`EndTurn`、`Surrender`、`SubmitMulligan`、`SubmitTargetChoice`、`RequestAct`、`RequestFusion`、`SendChatMessage`。参数以 [动作 DTO](../Server/Dtos/SignalR/Actions/) 和方法签名为准；不同方法并非都接收同一种请求对象。

连接时读取 `roomId` / 兼容 `gameId`、`playerId`、`token`，观战分支还读取 `spectate`、`joinCode` 等参数。连接上下文验证和动作权限应逐方法核对，别直接复用旧文档中的连接字符串示例。

`LogStreamHub` 当前读取 `userId` 并查询用户是否存在；`GetSnapshot(take)` 默认 200，限制在 0—1000。此实现不等于旧文档声称的 JWT 日志权限体系。

## 数据与迁移

实际 EF 模型：[ApplicationDbContext](../Server/Infrastructure/Data/ApplicationDbContext.cs)。主要实体组：

| 数据组 | DbSet 示例 |
|---|---|
| 卡牌与能力 | `CardDefinitions`、`CardAbilities`、`BuffDefinitions`、`TribeDefinitions` |
| 牌组与环境 | `UserDecks`、`UserDeckCards`、`DeckCardCopyLimitPolicies`、`CardSetDefinitions` |
| 用户与经济 | `Users`、`UserProfiles`、`UserEconomies`、`CoinTransactions`、`UserDailyRewards` |
| 活动任务 | `QuestDefinitions`、`UserQuests`、`QuestProgressEvents` |
| 社区 | `CardComments`、`CardVotes` |
| 对局与统计 | `GameSessions`、`GameSettlements`、`GameParticipantStatsFacts`、各聚合统计表 |
| 回放 | `ReplayGames`、`ReplayBundles`、`ReplayEvents`、`ReplaySnapshots` |

数据库配置走 `ConnectionStrings:DefaultConnection`，未配置时使用 `Data Source=Data/shadowverse.db`。应以实际工作目录和配置覆盖后的值确定文件位置，而不是只看历史文档。

当前迁移目录为 [Infrastructure/Persistence/Migrations](../Server/Infrastructure/Persistence/Migrations/)。[项目文件](../Server/ShadowverseBeyond.Server.csproj) 排除了嵌套 `Server` 等副本目录；仓库中看见另一套迁移文件，不代表它们都参与编译。修改数据库结构前先确认实际参与编译的迁移链和模型快照。

启动会应用迁移并执行 [DataSeeder](../Server/Infrastructure/Data/DataSeeder.cs)。它从内容根目录上一级的 `data` 目录读取种子；卡牌为空时枚举 `card_data*.json`，已有卡牌走相关回填逻辑。修改种子文件不等于立即覆盖在线数据库全部记录。

## 备份边界

数据库、卡图等上传资源和静态业务数据有不同存储位置。维护前同时确认 SQLite 文件、`assets/cards`、其他上传路径和配置；Git 中的代码/种子快照不是完整业务数据备份。实际发布目录布局见 [运行部署与排障](07-运行部署与排障.md)。
