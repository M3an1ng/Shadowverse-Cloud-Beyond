# 游戏界面目标功能地图与关键流程

> 定位：面向下一轮 UI/UX 与美术探索的目标设计，不是当前实现说明。
> 现状证据：[游戏界面功能地图.md](./游戏界面功能地图.md)。本文在重组现有能力的基础上，纳入卡牌图鉴、剧情战役、战术挑战和个性化大厅四个新增方向。
> 本次只更新设计文档；新增方向未实现，已有功能的新组织方式也未上线。旧的26张生图清单及其工作区方案不再约束本地图。
> A「星界航行」首页保留为品牌与空间气质参考，不冻结原有五入口、布局或全局装饰。

## 1. 设计目标与范围

让玩家在大厅同时感受到：有世界可探索、有对局可进行、有卡牌可欣赏、有内容可创作。丰富程度来自真实内容与个人进度，不来自更多同等大小的按钮。

本文使用三个状态标签：

| 标签 | 含义 | 使用边界 |
|---|---|---|
| 现有重组 | 能力在现状基线中有依据，目标改变导航、布局或流程组织 | 上下文恢复等新增交互仍需实现，不等于全部可直接使用 |
| 拟新增 | 本轮正式纳入目标地图的新系统或行为 | 需内容、数据与交互支持；概念图不是已上线证据 |
| 后续候选 | 有价值但不进入本轮核心设计的扩展 | 不提前占据正式首页入口 |

### 核心用户任务

- **探索者**：认识世界、推进剧情、完成挑战。
- **对战与构筑玩家**：找到卡牌、调整牌组、练习、联机或观战。
- **创作者**：制作卡牌、编辑能力与素材、验证作品。
- **管理者**：诊断状态、运行实验、维护规则与查看统计。

这些是使用同一产品时的任务身份，不新增账号角色或权限等级。

### 本轮范围

| 优先方向 | 纳入内容 | 能力状态 |
|---|---|---|
| 卡牌图鉴 | 公共目录、详细鉴赏、关键词、收藏、接续构筑 | 拟新增玩家入口与收藏行为，可复用现有卡牌数据与详情能力 |
| 剧情战役 | 章节、剧情片段、关卡准备、战斗、结果、进度 | 拟新增；现有未开放入口不算剧情系统 |
| 战术挑战 | 预设局面、目标、重置、分级提示、完成记录 | 拟新增；不把对战实验室等同于挑战系统 |
| 个性化大厅 | 展示卡、当前牌组、场景选择、个人内容状态 | 拟新增大厅表现与偏好持久化；战场桌布能力不等于大厅定制 |
| 对战、构筑、创作、工具 | 保留能力，重排流程与界面边界 | 现有重组 |

个人战绩、牌组方案库、世界档案、作品分享、好友邀请保留为后续候选。商城、抽卡、分解、通行证、公会和排位系统不因填充首页而进入本轮范围。

## 2. 顶层目标地图

一级主入口固定为 **旅程、对战、卡牌、创作**。大厅是共同起点；工具中心属于辅助工作入口。

```text
大厅 / 星界观测台
├─ 旅程 [拟新增]
│  ├─ 剧情战役
│  │  ├─ 章节总览 → 剧情片段 → 关卡准备
│  │  └─ 剧情对战 → 关卡结果 → 后续剧情 / 章节总览
│  └─ 战术挑战
│     └─ 挑战目录 → 目标与局面 → 挑战对战 → 结果 / 重试
├─ 对战 [现有重组]
│  ├─ 自由练习 → 人机 / 本地双人准备 → 对战 → 结果
│  ├─ 多人联机 → 创建或加入 → 房间准备 → 对战 → 结果
│  └─ 观战 → GameId / 房间列表 → 只读观战 → 返回来源
├─ 卡牌
│  ├─ 卡牌图鉴 [拟新增入口]
│  │  └─ 浏览 / 搜索 → 条目详情 / 大图 / 关键词 / 收藏
│  └─ 我的牌组 [现有重组]
│     └─ 牌组库 → 新建 / 导入 / 选择 → 构筑工作区
├─ 创作 [现有重组]
│  ├─ 创作库 → 卡牌工作区 → 属性 / 能力 / 素材
│  ├─ 能力结构编辑（DSL）
│  └─ 领袖与类型设定（现有“玩家设定”）
└─ 辅助入口
   ├─ 用户与认证 / 日常任务 / 关于与安装
   ├─ 大厅展示设置 [拟新增]
   └─ 工具中心
      ├─ 日志 / 控制台 / API测试
      ├─ 对战实验室 / 深入DSL入口
      ├─ 胜率统计 / 数据库查看器（开发中）
      └─ 用户 / 禁限卡牌 / 环境卡包管理（管理员）
```

“卡牌图鉴”面向浏览者，“我的牌组”面向构筑者，“创作库”面向编辑者，三者不再都叫“卡牌库”。图鉴的“收藏”是个人书签，不表示拥有卡牌。

路径是用户可理解的层级，不预先指定URL或要求为每个节点新建路由。全局“返回大厅”和局部“返回来源”承担不同职责。

## 3. 大厅：用内容建立丰富程度

### 3.1 四层内容，不是四块等大面板

| 层次 | 内容 | A主题中的设计方向 | 主要去向 |
|---|---|---|---|
| 世界层 | 当前章节、目的地、故事进度 | 观测台外的目的地、星图上的当前航路 | 旅程 / 当前章节 |
| 主行动层 | 开启或继续旅程、进入对战 | 一个最明确的主动作，另一项为稳定次入口 | 旅程或对战准备 |
| 个人层 | 指定展示卡、当前牌组、展示偏好 | 收藏展示位和简短牌组摘要，不做表单面板 | 图鉴条目 / 我的牌组 |
| 轻量动态层 | 当前挑战、可领取任务、真实版本变化 | 少量边缘信息，不遮盖场景和主行动 | 对应任务或条目 |

一级导航始终可见、位置稳定；内容模块不重复堆出第二套同等醒目的导航。场景物件可承载入口，但同时给出清楚的文字、选中/悬停反馈与键盘焦点。

### 3.2 首页代表状态

| 状态 | 主行动 | 次要内容 | 避免的误导 |
|---|---|---|---|
| 新玩家、无剧情进度 | 开启旅程 | 对战入口、预设展示卡、首个可用挑战 | 不显示“继续”或虚构的完成率 |
| 有剧情进度 | 继续旅程 | 当前章节与下一关、当前牌组 | 不跳过玩家上次尚未看完的剧情 |
| 玩家主动选择对战为快捷方向 | 进入对战 | 旅程仍在固定导航中、最近合法牌组 | 不因一次浏览自动改变主页结构 |
| 无合法牌组 | 主行动随任务确定 | 进入牌组的修复入口；剧情指定牌组不受此限制 | 不伪装可立即开始自由对战 |
| 内容未发布或不可用 | 其他真实可用动作 | 如需预告，明确未开放且不占主动作位 | 不填造章节、任务或“在线人数” |

主页快捷方向选择属于拟新增偏好。未做偏好功能前，默认旅程为主行动、对战为稳定次入口；不设计复杂的自动推荐算法。

### 3.3 个性化大厅

首批拟新增：选择一张图鉴卡作为展示卡、切换已提供的大厅背景、选择当前牌组、保存这些展示偏好。恢复默认只影响展示，不改牌组或卡牌数据。

后续可扩展主战者外观展示，但需独立确认可选资源；显示角色不等于改变对战领袖能力。原有战场桌布仍是战场工具，不混用大厅背景设置。

大厅不显示草稿数量、最近对局或最近编辑摘要，除非已有相应记录并完成接入；没有数据时给出真实空态或进入对应场域的入口。

## 4. 旅程：剧情与挑战分工

### 4.1 剧情战役 [拟新增]

核心循环：章节选择 → 剧情片段 → 关卡准备 → 对战 → 结果 → 后续剧情与进度更新。

- 章节总览包含章节名称、简介、进度和可进入状态；先完成一段完整旅程，不以巨大空白地图替代内容。
- 剧情片段支持继续、跳过与已读内容重看；章节进度与剧情阅读位置分别记录。
- 角色剧情关默认使用指定牌组，准备页解释目标和牌组，不强迫玩家先创建自己的构筑。
- 失败可重试或回章节；成功只在有效结果确认后推进对应节点。
- 中途离开说明本次尝试是否丢失，不删除已完成章节；首批不承诺对局中断点续玩。
- 暂不设计剧情奖励货币、角色养成或卡牌所有权解锁。需要奖励时另立明确规则，先以章节推进和完成记录闭环。

依赖：章节与节点内容、对话资源、指定牌组/敌方配置、开始与结果契约、进度存储、解锁条件。既有对战引擎可评估复用，但这些系统尚未实现。

### 4.2 战术挑战 [拟新增]

首批采用可复现的局面解谜与机制试炼；自带牌组的自由挑战是另一类设计，留待后续，不与剧情指定牌组混用。

- 目录按机制和难度组织；详情给出固定局面、目标与限制。
- 进入挑战后突出目标，支持重置当前尝试、请求分级提示、返回目录。
- 成功/失败按挑战目标判定，不只沿用普通对局胜负；例如“本回合获胜”还需核对回合边界。
- 重试恢复预设局面及随机条件，结果记录挑战版本与提示使用情况；首批不加入排名或奖励经济。
- 教学试炼解释单一机制，解谜试炼允许组合思考，避免把测试参数页直接交给玩家。

依赖：局面序列化/恢复、目标判定、提示内容、确定性条件和完成记录。对战实验室的起始参数不足以证明上述能力存在。

### 4.3 内容状态

未发布与锁定分开：未发布表示内容未开放；锁定表示内容已发布但前置条件未满足，需说明条件。加载失败不表现成“尚未解锁”，重试不抹除已有进度。

世界观文本先附着于章节与图鉴条目。跨角色、阵营和地点的独立世界档案作为后续候选，不先造一个空入口。

## 5. 对战：准备、房间与战场分离 [现有重组]

### 5.1 自由练习

人机对战和本地双人共享准备界面，均选择双方卡组并显示校验状态；对手字段随模式显示“AI卡组”或“第二位玩家卡组”。

剧情和战术挑战统一归旅程，不再在练习页重复放“剧情/地城未开放”的大入口。随机地城不进入本轮目标范围。

### 5.2 多人联机

- 未入房：当前卡组，创建或加入动作；加入只要求既有GameId和JoinCode。
- 创建/加入完成：进入房间状态，显示房间标识、双方座位/准备状态、适用规则和卡组校验。
- 等待对手：给出等待原因及离开房间；不继续展示创建/加入表单。
- 对手或连接状态变化：清楚反馈并依据当前状态决定进入对战是否可用。
- 不默认新增房间聊天、公开性、回合时长、先后手选择等尚未确认的房间能力。

### 5.3 观战

观战是独立只读分支，不经过本人卡组选择、就绪和投降流程。通过GameId或房间列表进入；房间失效/对局结束时解释状态，退出返回来源列表并保留筛选。

### 5.4 战场与结果

战场以牌面、双方资源、行动状态为中心；详情按需展开，表情与桌布放在战场辅助菜单。用户、任务、关于退到次级菜单，不占战斗核心视野。

结果页共用视觉骨架，但动作由来源决定：练习返回准备，剧情继续节点或回章节，挑战重试或回目录，联机回大厅。房间可复用及回房能力需核实，首批不承诺“原房间再战”。

活动中的普通对局离开需确认投降；剧情/挑战确认结束当前尝试；观战仅退出观看，不显示投降。系统断线用独立连接状态解释，不冒充用户主动投降或已成功重连。

## 6. 卡牌：图鉴与我的牌组

### 6.1 卡牌图鉴 [拟新增玩家入口]

图鉴是公共卡牌目录，不是商城或拥有权仓库。默认展示当前对用户可见的卡牌；收藏只是书签，已浏览是阅读状态，可用性由目标环境/规则决定。

- 浏览：搜索、职业/类型/费用/稀有度/卡包筛选、排序与分页；筛选条件可清除。
- 条目：大图鉴赏、属性、能力、关键词、所属卡包、相关卡牌；有真实世界观内容时再显示故事。
- 操作：收藏/取消收藏、设为大厅展示、加入指定牌组；权限允许时才显示在工坊打开。
- 图鉴可用独立详情视图；构筑或战场中的同一卡牌优先就地检查，不强制切到图鉴首页。
- 没有条目、素材缺失和网络错误分别说明；不补造背景故事或卡图。
- 首批不引入未拥有、购买、分解、卡包抽取、收藏完成率等奖励经济表达。

图鉴、构筑、工坊应引用同一卡牌身份及适用版本，避免各自维护属性副本。后续卡牌修改影响当前牌组时，应提示重新校验；收藏或展示卡失效时提示重新选择，不静默指向另一张牌。

### 6.2 我的牌组 [现有重组]

牌组库负责新建、导入、选择、复制与删除；构筑工作区负责搜索、加减数量、比较、规则校验和保存。新建/导入在工作区只保留快捷入口，不重复铺开完整管理列表。

构筑区让卡牌目录与当前构筑同时可见；详情侧栏保留搜索、分页、滚动和选中位置。费用曲线辅助判断，不抢过卡牌名称与数量。导出、保存、删除与单卡加减分开组织。

### 6.3 从图鉴加入牌组 [拟新增衔接]

选择卡牌 → 选择目标牌组 → 检查环境/复制上限 → 进入该牌组的待保存构筑。使用明确反馈“已加入待保存构筑”，不直接覆盖服务器牌组。

没有牌组时转入空白创建并保留待加入卡；规则不兼容时说明原因并允许选其他牌组。离开时沿用未保存处理，不把收藏动作误当加入构筑。

## 7. 创作：围绕作品组织 [现有重组]

创作库 → 选择/新建卡牌 → 卡牌工作区（基础属性、能力、素材）→ 校验与保存 → 返回创作库。

- 能力使用结构化字段；DSL是深入编辑方式，保留从工具中心直接进入的辅助路径，不成为玩家一级导航。
- 卡牌预览与当前字段同时可见；素材裁切是专用编辑状态，应用后先回到待保存卡牌。
- 现有“玩家设定”面向领袖能力和种族/类型管理，目标称“领袖与类型设定”，放在创作场域的独立子区；它不属于个人账号外观，也不假定只影响当前卡牌。
- 从图鉴进入工坊时携带卡牌身份和返回来源，权限以现有规则核验，本文不扩大编辑授权。
- 从工坊进入实验室验证作品时，先明确使用已保存版本；未保存内容先处理，实验结果返回原作品上下文。
- 作品公开发布、社区精选与分享库是后续候选，当前保存不等于发布。

## 8. 辅助入口、设置与工具

| 入口 | 目标组织 | 边界 |
|---|---|---|
| 用户与认证 | 全局账号面板，完成后回原任务 | 不凭页面可见性推断所有动作可匿名执行 |
| 日常任务 | 全局抽屉；首页仅露出可领取摘要 | 每日奖励与任务奖励按真实规则分别处理，不添加完成全部任务的前置条件 |
| 关于与安装 | 版本、真实技术信息、更新日志与PWA | 无更新内容时不编造公告 |
| 大厅展示设置 | 从个人展示位或辅助菜单进入 | 只管理展示偏好，不调整卡牌、领袖规则或战场桌布 |
| 工具中心 | 辅助入口和创作上下文捷径 | 不再与旅程、对战、卡牌、创作等权 |
| 普通玩家设置 | 待核对实际可调选项后组织 | 不为了凑设置页编造音画开关、快捷键或其他未确认能力 |

工具中心内部保留：诊断（日志/控制台/API）、实验（对战实验室）、数据统计（胜率）、管理员管理（用户/禁限/环境卡包）。数据库查看器维持开发中；DSL捷径指向同一能力编辑工作区，不复制另一套编辑器。

访问遵循现有权限核验：实验室和现有工具登录要求保留，用户/禁限/环境卡包管理需管理员；其他具体动作按实现核对。辅助入口可按任务与权限显隐，直接访问受限位置仍给出原因。

## 9. 关键流程与返回契约

以下是目标交互流程；“记住上下文、登录后返回、个人偏好持久化”等行为属于待实现要求。

| 流程 | 主线 | 完成与返回 | 异常/中断 |
|---|---|---|---|
| 首次旅程 | 大厅开启 → 首章 → 剧情 → 指定牌组准备 → 剧情战斗 | 结果确认后推进；大厅显示继续旅程 | 失败回关卡；中途离开保留已完成进度 |
| 继续剧情 | 大厅继续 → 最近可恢复剧情位置/关卡准备 | 重看不重置通关状态 | 对局中断点续玩不在首批承诺内 |
| 战术挑战 | 目录 → 目标/局面 → 开始 → 判定 | 记录完成和提示使用；重试/下一挑战/回目录 | 重置恢复同一预设；规则失效时明确不可用 |
| 自由练习 | 模式 → 双方卡组 → 校验 → 战斗 | 结果 → 原准备页，保留模式与卡组 | 无合法牌组进入修复，回来重新校验 |
| 多人联机 | 卡组 → 创建或加入 → 房间 → 双方准备 → 对战 | 结果 → 联机大厅；回房另行核实 | 加入失败留在表单；离房/投降分别处理 |
| 观战 | GameId或列表 → 只读对局 | 返回来源列表与筛选位置 | 房间失效给出刷新/返回，不要求选择牌组 |
| 图鉴浏览 | 搜索筛选 → 条目 → 大图/关键词/收藏 | 返回原列表位置；展示操作回大厅 | 条目失效保留返回路径；不伪装无搜索结果 |
| 图鉴转构筑 | 条目 → 选目标牌组 → 兼容校验 → 待保存构筑 | 保存后明确成功，可回原图鉴条目 | 满额或不兼容说明原因；失败不改原牌组 |
| 牌组创建/导入 | 库 → 空白创建或代码解析预览 → 构筑 → 校验 → 保存 | 回库或接续原对战准备 | 解析失败不覆盖；校验失败定位具体卡牌/数量 |
| 卡牌创作 | 创作库 → 属性/能力/素材 → 校验 → 保存 | 回库恢复筛选；来自图鉴则可回原条目 | 保存失败保留输入；离开询问保存/放弃/继续编辑 |
| 大厅定制 | 展示设置 → 选择可用卡图/背景 → 预览 → 应用 | 返回大厅并确认已应用 | 取消恢复先前展示；失效资源提示重新选择 |
| 登录后继续 | 触发需账号动作 → 认证 → 返回原上下文 | 重新核验动作前提，用户确认后执行 | 不自动重放创建房间、领取、删除等有副作用动作 |
| 管理操作 | 权限 → 筛选 → 选择记录 → 修改 → 保存 | 列表保留位置并显示结果 | 删除/重置密码需确认；权限失效停止提交 |

### 统一的上下文与状态原则

1. 记住来源、当前对象、筛选/分页/滚动位置；返回不总是回大厅。当前对局、卡牌草稿和剧情阅读位置分别管理。
2. 在普通对局中使用自选牌组时，数量、环境与规则需通过校验；剧情指定牌组和挑战预设局面使用各自已验证配置，不强套40张自选牌组门槛。实验室沿用其独立测试规则，观战不要求牌组。
3. 编辑草稿与已保存数据区分；首批保持显式保存，不将界面重排等同于自动保存或跨设备草稿同步。
4. 已保存与失败明确区分。进度/收藏/偏好提交失败时保留当前上下文并提供重试，不显示虚假成功。
5. 章节进度、挑战完成、卡牌书签、当前构筑是独立状态；改变其中一项不隐式改变其余项。
6. 已登录不表示有编辑或管理员权限；未登录可浏览的范围需按现有读取权限及新增系统访问设计确认，不提前宣称所有牌组可匿名读。
7. 加载、空结果、未开放、前置未满足、权限不足、连接失败分别表达；颜色之外有文字或标记。
8. 卡牌/挑战/章节配置更新后需验证引用有效性；完成记录关联内容身份与版本，不把修改中的素材当成固定关卡规则。

## 10. 容器与视觉职责

| 场域/交互 | 默认容器 | 视觉重点 |
|---|---|---|
| 大厅 | 完整场景与清晰导航 | 品牌、目的地、个人展示；保留场景呼吸空间 |
| 剧情阅读/章节总览 | 专属叙事视图/章节视图 | 角色、地点、阅读顺序与继续动作 |
| 挑战目标/结果 | 战斗前后轻量专属状态 | 目标、限制、成功原因与重试 |
| 图鉴条目 | 鉴赏视图，大图可展开 | 卡牌插画、属性、关键词与关联 |
| 构筑中的卡牌详情 | 就地侧栏 | 不丢失卡牌比较与构筑上下文 |
| 卡牌创作 | 字段区与固定预览区 | 当前作品、当前编辑任务、保存状态 |
| 战场 | 牌局主导的完整视图 | 双方资源、牌面与行动；背景退让 |
| 日志/统计/管理 | 停靠区或完整工作区 | 数据扫描与操作后果；小品牌标识即可 |
| 退出/删除/重置密码 | 模态确认 | 具体后果、对象与取消路径 |
| 认证/任务/关于 | 轻量面板或抽屉 | 完成后恢复原任务，不层层套弹窗 |
| 素材裁切 | 专用编辑状态 | 操作范围、预览、应用与取消 |

同一主题继承色彩角色、卡框、字体层级、图标语义和状态反馈，不要求每页出现星空大图、金框或圆环。卡牌是创作/图鉴中的主要丰富视觉资产；普通字段、表格和日志不逐项发光。

有艺术叙事的页面保留空间感，数据页面允许简洁；“统一”不等于统一装饰强度。概念图的数据和剧情内容在交付索引中标明示例，不用满屏说明文字干扰画面。

## 13. 下一轮探索与验收

### 13.1 先验证流程，再画完整风格

1. 低装饰布局：大厅的内容层次、章节/挑战入口、图鉴到构筑、联机房间、创作与工具的主次关系。
2. 关键流程串联：首次旅程、有进度返回、挑战重置、图鉴加入牌组、认证后继续、编辑未保存离开。
3. A主题代表图：新大厅、章节/剧情代表状态、图鉴详情、战场、构筑、卡牌创作。先检查空间与层级，少量金属细节不作为通过依据。
4. 再验证挑战、联机、工具和必要浮层；单一界面只展示一个合理状态，不将整条流程拼成一张图。
5. 由选定流程建立新的页面/状态编号；常态、空态、失败态各按风险选择，不照抄旧26张清单，不再次先做全部高精图。

### 13.2 可检查的通过条件

- 新玩家能找到四个主要去向；工具中心与账号功能没有压过玩家内容。
- 无剧情进度显示开启，有进度显示继续；没有内容的区域不伪装可进入。
- 图鉴收藏、设为展示、加入牌组三个动作与结果可区分，均不引入卡牌所有权。
- 指定牌组剧情与预设局面挑战不被自由构筑校验误拦；观战不要求就绪或投降。
- 多人入房后不再并排显示创建/加入表单；退出对局与离开房间后果各自明确。
- 构筑查详情、工坊裁切、认证返回均保留当前对象和操作位置。
- 每屏主要对象与动作清楚，卡牌/场景/字段之间有明确面积和视觉主次，装饰不依靠框套框和满屏高亮。
- 权限、未保存、无内容、加载失败有独立表达；成功反馈有真实结果依据。
- 跨页样例牌身份/属性/角标一致，示例内容与真实功能状态在交付说明中区分。

### 13.3 后续实现前再细化

剧情文本与章节数量、挑战题目及目标格式、内容版本策略、匿名进度与账号同步规则、收藏/偏好的持久化范围、对局结果提交与重试策略，需要后续分别定义；首批不默认承诺云存档、实时断线恢复或战斗中存档。

导航层级与内容支柱按本文推进；URL划分、具体布局、字段尺寸和动效在低保真验证后决定。本文件不要求再次征询这些已确定的顶层方向。
