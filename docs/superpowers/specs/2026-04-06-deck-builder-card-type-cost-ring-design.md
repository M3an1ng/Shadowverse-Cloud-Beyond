# 卡组编辑界面卡牌类型费用圈区分设计

日期：2026-04-06

## 背景

当前卡组编辑界面中，主编辑区牌库卡、已选卡缩略卡、卡组预览弹窗卡片，虽然都能显示费用、名称、稀有度等信息，但“从者 / 法术 / 护符”三种主构筑类型的视觉差异不够明显。

现状中，类型信息主要依赖：

- 顶部统计区 `type-counts` 的文字颜色
- 卡牌正文中的类型文本
- 从者额外显示的攻防数值

这些信号在浏览大量卡片时不够直接，尤其是在缩略尺寸下，一眼判断类型的成本偏高。

## 目标

在不破坏现有卡牌边框、稀有度边框和整体视觉和谐度的前提下，为三种主构筑类型增加统一、轻量、稳定的视觉区分信号。

本次设计目标：

- 提高“从者 / 法术 / 护符”的首眼辨识度
- 保持现有稀有度边框体系不变
- 保持卡面主体结构不变
- 让主编辑区与卡组预览弹窗的视觉规则一致
- 限制改动范围，避免演化成整页重设计

## 不做的内容

本次设计明确不包含以下内容：

- 不修改卡牌整体边框颜色
- 不增加整卡类型描边
- 不改变卡牌名称区、卡面区、hover 蒙层结构
- 不为 `Crest / Faith / Leader` 等非主构筑类型设计新配色
- 不调整顶部统计区 `type-counts` 的现有配色方案

## 设计结论

采用“B 方案的收敛版”：

- 保留 B 方案的“在卡片本体中体现类型差异”的方向
- 但只使用费用圈作为类型区分信号
- 不让类型颜色参与卡框本体

这意味着本次落地后，卡片的类型识别完全由费用圈承担：

- 费用圈描边颜色
- 费用数字颜色
- hover 时费用圈的轻微同色辉光

除费用圈以外，卡片其他区域保持当前表现。

## 颜色映射

类型颜色直接复用当前 `type-counts` 的语义配色，避免顶部统计区与卡片本体出现两套颜色语言。

- 从者：红色 `#ef4444`
- 法术：紫色 `#a78bfa`
- 护符：绿色 `#32ab5e`

默认回退颜色保持当前费用圈风格：

- 未知类型 / 非本次覆盖类型：青色系，沿用当前默认费用圈颜色

## 适用范围

本次设计同步应用于以下三处：

1. 卡组编辑主界面的牌库卡
2. 卡组编辑主界面的已选卡缩略卡
3. 卡组预览弹窗中的卡片

对应实现位置：

- `src/deckBuilder.js`
- `src/components/deckPreviewModal.js`
- `src/styles/deck-builder.css`

## 视觉规则

### 1. 牌库卡

作用对象：`.library-card .card-cost`

规则：

- 从者卡：费用圈描边、数字改为红色
- 法术卡：费用圈描边、数字改为紫色
- 护符卡：费用圈描边、数字改为绿色
- hover 时仅增加一层轻微同色辉光
- 卡牌整体 hover 效果保持现状

### 2. 已选卡缩略卡

作用对象：`.mini-cost`

规则与牌库卡一致：

- 只改费用圈颜色
- 不改缩略卡边框
- 不改底部名称区域
- 不改移除态红色蒙层逻辑

### 3. 卡组预览弹窗卡片

作用对象：`.deck-preview-card-cost`

规则与前两处一致：

- 使用同一套类型颜色
- hover 仅增加轻微同色辉光
- 保持与主编辑界面一致的识别规则

## 结构设计

为避免三处卡片各写一套判断逻辑，统一在卡片根节点增加类型 class。

建议 class：

- `type-follower`
- `type-spell`
- `type-amulet`

生成逻辑：

- 在主编辑区牌库卡渲染时为 `.library-card` 增加类型 class
- 在已选卡缩略卡渲染时为 `.deck-card-mini` 增加类型 class
- 在卡组预览弹窗渲染时为 `.deck-preview-card` 增加类型 class

CSS 统一通过卡片根节点类型 class 控制内部费用圈样式，例如：

- `.library-card.type-follower .card-cost`
- `.deck-card-mini.type-spell .mini-cost`
- `.deck-preview-card.type-amulet .deck-preview-card-cost`

这样可以避免在费用圈元素上重复塞业务 class，也方便后续扩展。

## 交互规则

交互强度保持克制，避免费用圈成为过强焦点。

默认态：

- 费用圈 1px 类型色描边
- 费用数字使用相同类型色

hover 态：

- 费用圈增加轻量同色辉光
- 不增加脉冲、动画、扩散描边等动效

点击、选中、详情按钮、移除操作：

- 保持现有交互逻辑不变
- 类型颜色不参与额外状态机

## 边界情况

### 主构筑类型

- 从者：保留现有攻防显示
- 法术：不显示攻防，仅靠费用圈颜色识别
- 护符：不显示攻防，仅靠费用圈颜色识别

### 其他类型

以下类型不在本次新增配色范围内：

- `Crest`
- `Faith`
- `Leader`
- 其他未知或扩展类型

这些类型统一回退到当前默认青色费用圈，确保：

- 页面不会出现无样式卡
- 不会因为类型扩展导致样式缺口
- 本次范围保持聚焦

### 数据异常

若卡牌类型为空、未知或枚举值不在预期集合内：

- 使用默认费用圈样式
- 不抛出 UI 异常
- 不影响卡牌渲染

## 方案权衡

### 为什么不改卡牌边框

用户已明确指出，多层颜色叠加在一起不和谐。

现有界面中卡牌边框已经承担了稀有度表达：

- Bronze
- Silver
- Gold
- Legend

如果再让类型颜色进入卡框，会出现以下问题：

- 类型与稀有度抢夺同一视觉层级
- 颜色叠加导致卡片显得杂乱
- 传奇卡的特殊边框更容易被破坏

因此本设计将类型信号收敛到费用圈，避免语义冲突。

### 为什么不只用文字标签

纯文字标签虽然实现成本低，但在浏览密集卡片时不够高效，尤其是在：

- 缩略卡尺寸较小
- 玩家快速扫视卡堆
- 预览弹窗横向大量排布时

费用圈位于卡片左上角，是天然高频被扫到的位置，更适合作为类型首眼信号。

## 实现建议

建议按以下顺序实施：

1. 在三种卡片根节点上统一补充类型 class
2. 在 `deck-builder.css` 中抽出统一的类型费用圈变量或规则
3. 为三种费用圈选择器接入同一套类型样式
4. 验证默认态与 hover 态是否一致
5. 验证预览弹窗与主编辑页视觉是否一致

## 测试与验收

验收关注点：

- 从者 / 法术 / 护符在三处视图中的费用圈颜色一致
- 稀有度边框未被破坏
- hover 时费用圈增强但不过亮
- 传奇卡、无图卡、普通卡都保持协调
- 未知类型卡牌仍能正常显示

建议验证组合：

- 从者 + Bronze / Gold / Legend
- 法术 + Bronze / Gold / Legend
- 护符 + Bronze / Gold / Legend
- 无图片卡牌
- 预览弹窗内大量卡片横向滚动场景

## 风险与控制

风险较低，主要集中在样式一致性：

- 三处卡片样式选择器不同，容易漏改
- 某些旧数据类型值可能大小写或命名不一致
- hover 辉光如果过强，会导致费用圈比卡名更抢眼

控制方式：

- 统一类型标准化逻辑
- 使用根节点类型 class 而非在 CSS 中重复写类型判断
- 辉光强度保持轻量

## 最终结论

本次设计以“最小有效改动”为原则：

- 不改卡框
- 不改稀有度表达
- 不扩展更多类型
- 只用费用圈为“从者 / 法术 / 护符”建立统一识别语言

这是当前卡组编辑界面中识别度、和谐性、实现成本三者之间最平衡的方案。
