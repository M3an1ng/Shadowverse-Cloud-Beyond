# DSL 编辑器重构设计文档（v1）

## 1. 目标与范围
- 用统一的“主表达式 + 工作区”模型，持续编辑一个“单一复杂主表达式”（而不是多个表达式列表），主表达式保持可见与不变，工作区用于编辑主表达式中的某个子表达式或整个主表达式最外层。
- 严格复用原有的 dsl-encapsulated-expression 封装样式（绿色背景框 + 对勾）来显示每个已封装的子表达式，层次清晰可视。
- 正确处理操作符对“是否需要新表达式”的控制逻辑，保存时进入正确的“回到上一级继续编辑”而不是清空工作区。
- 正确标识“当前正在编辑”的表达式（在主表达式中以特殊样式高亮）。
- 修复“封装逻辑 BUG”：在 (6) > 5 保存时，先封装 5 为 (5)，而不是把整个表达式封装成 ((6) > 5)。

## 2. 关键概念与状态模型

### 2.1 主表达式 MainExpressionAST
- 指用户正在构建/维护的唯一复杂表达式树。始终显示在上方，不因工作区编辑而“消失”或“错乱”。
- 每个封装好的子表达式使用 dsl-encapsulated-expression 样式渲染（绿色 capsule 框体 + 对勾）。
- 主表达式最外层也是一个“封装表达式”。点击最外层可以把“整个主表达式”作为一个封装好的左操作数移入工作区，继续扩展（如添加 &&、|| 等）。

### 2.2 工作区 WorkspaceAST
- 承载“当前编辑”的表达式（可以是某个子表达式，或整个主表达式的封装体），编辑完成后保存回主表达式相应位置。
- 保存后并不清空工作区，而是“回到上一级”继续编辑（如从编辑右操作数回到编辑操作符，或从子表达式回到包裹它的更高一层封装）。
- 只有在确定“完成本层编辑并返回上一层”时才会退出当前编辑层级，层层返回，直至回到主表达式顶层。

### 2.3 编辑路径 EditingPath（栈）
- 用栈结构记录“从主表达式到当前工作区节点”的路径，包括父节点、槽位（left/right/self）、封装 metadata 等。
- 保存时通过栈顶信息将工作区表达式回填到主表达式中正确位置，然后“出栈返回上一级”。

### 2.4 当前编辑标识 CurrentHighlight
- 主表达式渲染中，对应该工作区目标子表达式节点，在 UI 上使用“特殊高亮框”强调（黄色描边或虚线边框，附小标签“编辑中”），不同于绿色封装框。

## 3. UI 设计规范

### 3.1 主表达式区（上方）
- 结构
  - 标题：主表达式
  - 表达式树：每个封装子表达式使用“dsl-encapsulated-expression”样式（绿色背景框体 + 对勾）渲染。
  - 当前编辑高亮：若存在工作区编辑目标，对应的子表达式采用“高亮样式”（黄色描边/浅黄背景）包裹在绿色封装框外层或侧边标注“编辑中”。
- 交互
  - 点击任一封装子表达式：将该子表达式的“内部 AST”复制到工作区，并在主表达式侧保留原封装（主表达式保持不变），仅对其显示“编辑中”标识。
  - 点击最外层封装：将主表达式封装体整体作为左操作数进入工作区（用于继续扩展 &&、|| 等逻辑）。
- 样式
  - dsl-encapsulated-expression：延用已有绿色 capsule 样式，完整表达式显示对勾。
  - current-edit-highlight：黄色边框 + 附加“编辑中”Badge，不显示对勾。

### 3.2 工作区（下方）
- 结构
  - 标题：工作区（正在编辑：<节点类型和位置>）
  - 编辑面板：复用节点链编辑 UI（选项菜单、输入、操作符添加等）
  - 操作按钮：保存（✓）、返回上级（←）、取消、完成并回到主表达式（Done 到顶）
- 状态管理
  - 不清空工作区：保存（✓）时写回主表达式对应节点，然后回到“上一层编辑”。
  - 清空条件：仅“完成并回到主表达式”（顶层 Done）时，清空工作区并取消当前编辑高亮。
- 样式建议
  - 黄色温和背景块（#fff7e6），细黄色边框（#ffec99），与主表达式区视觉区隔。

## 4. AST 逻辑与封装/保存流程

### 4.1 AST 节点类型
- ValueNode：封装表达式的节点（metadata.type === "encapsulated"；innerAST 指向内部真实表达式树）。也可代表未封装的原子值（literal）。
- OperatorNode：操作符节点，leftOperand、rightOperand 可为空或指向子表达式节点。

### 4.2 编辑路径与回填
- EditingPath 栈项结构
  - parentNode: 父节点引用（ValueNode 或 OperatorNode）
  - slot: "left" | "right" | "self"
  - encapsulated: boolean（父层是否以封装体包裹）
  - descriptor: 文本描述（如“右操作数”、“封装体内部”）用于 UI 标注
- 写回规则
  - 保存（✓）时，将 WorkspaceAST 封装为“封装 ValueNode”（displayValue="(…)"，innerAST=WorkspaceAST），替换到 EditingPath.top 指示的位置：
    - slot=left/right：parent.setLeftOperand(newValueNode)/setRightOperand(newValueNode)
    - slot=self：替换父的 innerAST 或替换父在其上层的引用（由上层路径项决定）
  - 写回后“出栈一层”，WorkspaceAST 切换为上一层需要继续编辑的节点内 AST（工作区不清空）。
- 当前编辑标识
  - 主表达式渲染时，通过 EditingPath.top（parent+slot）定位目标子树，在对应封装组件上加“高亮”样式。

### 4.3 操作符与工作区切换逻辑
- 二元操作符（如 >）
  - 将封装体作为左操作数：创建 OperatorNode（left=当前封装体，right=null），工作区转向 right（需要新表达式），压栈 {parent=OperatorNode, slot="right"}。
- 一元/无需新表达式的操作
  - 按操作定义决定是否进入新子表达式编辑；若不需要，则留在当前层编辑即可。

### 4.4 封装/保存行为
- 保存（✓）：只保存“当前工作区编辑对象”到主表达式槽位，再回到上一层继续编辑；不会整体封装主表达式。
- 完成（顶层 Done）：从当前层层返回，直到回到最顶层；最终清空工作区并取消主表达式的“编辑高亮”。
- 退回（←）：放弃当前层工作区修改，回到上一层（不写回）。

### 4.5 BUG 场景修复
- (6) > 5：
  - 当前在右操作数编辑“5”；保存（✓）仅封装为 (5)，写回 OperatorNode.right，并回到 OperatorNode 层。绝不整体封装为 ((6) > 5)。

## 5. 用户交互流程（举例）

### 5.1 (( (context.sourceCard.health) + (2) ) > (5))
- 点击 (2)：主表达式 (2) 外侧出现“编辑中”高亮；工作区载入 innerAST=2；保存为 (3) -> 写回 +.right -> 回到 + 层；可继续返回到 > 层、顶层。
- 扩展主表达式：点击最外层封装 -> 进入工作区选择 && -> 进入右操作数编辑 -> 保存回写 -> 在 && 层确认 -> Done 回到主表达式，主表达式更新为 (旧) && (新)。

## 10. 交互改进：手动提升表达式层级

### 10.1 背景与目标

为了解决在复杂表达式中，用户难以精确控制运算优先级和组合范围的问题（如 `... && (5)`），我们引入一个对用户友好、直观的交互方式。此方案旨在允许用户**手动**将一个值或一个子表达式“提升”为一个独立的、可操作的表达式单元，而无需理解“封装”等技术概念，从而替代复杂的“智能封装”算法。

### 10.2 核心交互设计

#### 10.2.1 “提升层级”按钮

-   **视觉表现**: 在每个可以被“提升”的节点旁边，显示一个小巧、清晰的图标按钮。
    -   **图标建议**: `()` (括号图标)，直观传达“包裹”、“组合”的意图。
    -   **位置**: 紧邻对应节点的右侧，不干扰主表达式的阅读流。
    -   **可见性**: 建议在鼠标悬停于对应节点上时出现，以保持界面简洁。

-   **交互提示 (Tooltip)**: 当鼠标悬停在按钮上时，提供清晰、简单的文本提示。
    -   **文案建议**: “创建表达式”或“组合为单元”。

#### 10.2.2 适用节点

“提升层级”按钮应该出现在以下类型的节点旁边：

1.  **原子值节点**: 静态值（如 `5`）、上下文变量、属性访问等。
2.  **未被操作符连接的、已封装的表达式**: 允许用户进行二次封装，例如将 `((5))` 提升为 `(((5)))`。

### 10.3 工作流程示例

**场景**: 用户想构建表达式 `... && ((5) < (6))`，当前工作区为 `... && (5)`。

1.  **初始状态**: UI 显示 `... && (5)`。当鼠标悬停在 `(5)` 上时，其右侧出现一个 `()` 按钮。
2.  **用户操作**: 用户点击 `(5)` 旁边的 `()` 按钮。
3.  **系统响应**:
    -   **AST 变化**: 代表 `(5)` 的 `ValueNode` 被一个新的 `EncapsulatedNode` 包裹。
    -   **UI 更新**: 工作区的显示**立即**更新为 `... && ((5))`。
4.  **后续编辑**: 用户现在点击 `((5))` 这个整体，系统会将其识别为独立的左操作数，从而可以顺利地添加 `<` 操作符，工作区变为 `((5)) < (空白)`。

### 10.4 实施要点

-   **渲染器**: 修改UI渲染逻辑，在渲染“可提升”节点时，附加渲染“提升层级”按钮，并绑定节点的唯一ID或路径。
-   **事件处理器**: 创建 `handleElevateExpression(nodeId)` 函数，负责找到对应节点并执行AST的“包裹”操作，然后触发UI重绘。
