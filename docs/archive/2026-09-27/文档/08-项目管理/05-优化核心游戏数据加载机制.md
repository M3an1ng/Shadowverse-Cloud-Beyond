# 任务：优化核心静态游戏数据加载机制 - 采用预加载策略

## 1. 背景与问题

当前系统在处理核心静态游戏数据（如卡牌定义 `CardDefinition`、卡牌能力 `CardAbility`、预定义 Buff 模板 `BuffDefinition` 等）时，存在潜在的性能瓶颈。分析显示：

*   **能力加载:** 能力配置 (`AbilityConfig`) 似乎是在卡牌被打出时才通过 `AbilityLoader` 按需加载。
*   **卡牌定义加载:** `CardDefinition` 在游戏初始化时会全量加载一次用于构建牌库，但在每次打牌时会再次按需加载单个定义。
*   **Buff 定义加载:** 预定义的 Buff 模板 (`BuffDefinition`) 很可能也是在 `ApplyBuff` 效果触发时按需加载。

这种混合/按需加载模式存在以下风险：

*   **运行时延迟:** 频繁的数据库 I/O 操作可能导致玩家在执行核心游戏动作（打牌、触发能力/Buff）时感受到明显的卡顿。
*   **数据库压力:** 大量重复或按需的数据库查询在高并发场景下可能成为系统瓶颈。
*   **代码复杂性:** 在需要长期运行的服务（如 `GameService`）中处理需要访问数据库的 Scoped 依赖，增加了实现的复杂性。
*   **数据冗余:** 重复加载已有的 `CardDefinition` 等数据是低效的。

## 2. 任务目标

将核心静态游戏数据（`CardDefinition`、`CardAbility`、`BuffDefinition` 等）的加载方式统一改为“初始化时预加载”，存储在内存缓存中，以消除运行时的数据库访问延迟，提升游戏性能和响应速度。

## 3. 解决方案与实施步骤

1.  **创建/扩展统一数据提供者服务:**
    *   设计或扩展一个单例（Singleton）服务（例如 `GameDataProvider`）。
    *   职责：负责在应用启动时加载并缓存所有核心静态游戏数据。
    *   **设计考虑:** 采用灵活的内部结构（如多个字典），方便未来扩展以支持更多类型的数据（如复杂能力模板、规则配置等）。

2.  **实现预加载逻辑:**
    *   在应用程序启动阶段（例如 `Program.cs` 或 `IHostedService`），调用数据提供者服务的初始化方法。
    *   该方法从数据库加载所有 `CardDefinition`、`CardAbility`、`BuffDefinition` (假设存在对应实体/表) 等记录。
    *   将加载的数据存储在提供者服务的内存缓存中（例如 `Dictionary<int, CardDefinition>`、`Dictionary<long, AbilityConfig>`、`Dictionary<string, BuffDefinition>`）。

3.  **修改数据访问逻辑:**
    *   **`AbilityManager`:**
        *   注入 `GameDataProvider`。
        *   修改 `CreateAbilityFromConfig` 等方法，从缓存中获取 `AbilityConfig`。
        *   调整 `CreateAbilitiesForCard` 从缓存获取配置。**(确认 `AbilityIds` 填充)**
    *   **`GameService` (及相关依赖):**
        *   注入 `GameDataProvider`。
        *   修改 `FetchCardDataAsync` (或调用者)，从缓存获取 `CardDefinition`。
        *   修改 `GetOrCreateGameStateAsync`，使用缓存构建牌库。
        *   移除 `ProcessCardPlayAbilitiesAsync` 中对 `AbilityLoader` 的使用。
    *   **`BuffManager` / `ApplyBuff` 效果处理器:**
        *   注入 `GameDataProvider`。
        *   修改处理预定义 Buff 的逻辑，使其从缓存中获取 `BuffDefinition` 模板，而不是实时查询。

4.  **移除旧的加载代码:**
    *   清理 `GameService`、`AbilityLoader` (如果不再需要) 等处残留的按需加载数据库的代码。

5.  **更新文档:**
    *   在 [`文档/05-游戏系统/01-卡牌能力系统.md`](文档/05-游戏系统/01-卡牌能力系统.md) 中明确说明能力数据的预加载和缓存策略。
    *   在 [`文档/04-数据库设计/01-实体关系图.md`](文档/04-数据库设计/01-实体关系图.md) 或相关卡牌系统文档中说明 `CardDefinition` 的预加载策略。
    *   在 [`文档/05-游戏系统/10-动态效果与Buff系统.md`](文档/05-游戏系统/10-动态效果与Buff系统.md) 中明确说明预定义 Buff 模板的预加载策略。
    *   在 [`文档/02-后端架构/01-服务层设计.md`](文档/02-后端架构/01-服务层设计.md) 中描述新的数据提供者服务及其职责和扩展性设计。
    *   更新此任务文档的状态。

6.  **测试:**
    *   编写单元测试验证数据提供者服务的数据加载和缓存功能（覆盖所有数据类型）。
    *   编写集成测试或进行手动测试，确保在预加载模式下，卡牌信息、能力和 Buff 能够正确触发和执行。

### 4.3 已完成的核心优化成果

*   **数据库查询消除**: 移除了所有运行时的卡牌定义和能力配置数据库查询
*   **缓存命中率**: 所有静态游戏数据访问都通过预加载的内存缓存完成
*   **性能提升**: 消除了数据库I/O延迟，所有数据访问变为同步内存操作
*   **架构统一**: 通过 GameDataProvider 统一管理所有静态游戏数据访问
*   **依赖注入优化**: AbilityLoader 支持两种构造模式，优先使用缓存模式
*   **编译状态**: 编译错误保持在38个（都是之前存在的Guid/string类型转换问题）

*   ✅ **BuffDefinition预加载支持系统化实施**
    *   创建了完整的BuffDefinition实体，支持语义化ID、JSON配置、DSL表达式
    *   配置了数据库映射和索引，创建了数据库迁移文件
    *   扩展了GameDataProvider支持BuffDefinition的预加载和缓存访问
    *   创建了BuffDefinitionSeeder种子数据，包含基础关键字、属性修改、特殊效果Buff
    *   扩展了BuffFactory支持从BuffDefinition缓存创建Buff实例
    *   更新了Program.cs依赖注入配置，优先使用GameDataProvider构造函数
    *   更新了DiagnosticsController包含BuffDefinition统计信息和类型分布
