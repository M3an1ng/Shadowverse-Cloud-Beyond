# BUG-003: 攻击与卡牌连打问题报告

## 1. BUG描述

在修复了“随从战斗后生命值UI未立即更新”的BUG后，测试过程中发现了两个新的、严重影响游戏流程的问题。

### 问题一：随从无法攻击敌方主战者

*   **现象**:
    1.  当己方场上有可以攻击的随从时，可以正常选中该随从作为攻击者。
    2.  敌方主战者会被高亮显示，表明其为可攻击的合法目标。
    3.  点击敌方主战者后，没有任何事情发生。没有触发攻击事件，没有战斗结算，也没有错误提示。
    4.  发起攻击的随从的 `canAttack` 状态没有被消耗，它依然可以继续对其他合法的敌方随从发起攻击。
*   **预期行为**:
    *   点击敌方主战者后，应立刻触发攻击流程，向服务器发送攻击请求。
    *   服务器处理后，应广播相应的战斗结算事件（如 `DamageDealt`, `HealthChanged` 等）。
    *   攻击方随从在攻击后，其 `canAttack` 状态应被消耗（变为 `false`），本回合无法再次攻击。
*   **初步推测**:
    *   客户端 `gameManager.js` 的 `selectAttackTarget` 函数在处理主战者为目标时，可能未能正确构建或发送SignalR请求。
    *   服务端 `GameService.cs` 在接收到以主战者为目标的攻击请求时，可能未能正确识别目标实体，导致请求被静默丢弃。

### 问题二：单回合无法打出多张卡牌

*   **现象**:
    1.  在一个回合中，玩家可以正常打出第一张卡牌。
    2.  打出第一张牌后，手牌中其他满足费用和条件的卡牌，虽然UI上可能显示为可使用，但无法成功打出。
    3.  所有后续的出牌尝试均无响应。
    4.  必须结束当前回合，进入下一个回合后，出牌能力才会恢复正常。
*   **预期行为**:
    *   在一个回合中，只要玩家拥有足够的Play Points (PP)，就应该可以连续打出任意数量的卡牌。
*   **初步推测**:
    *   这是一个状态管理问题。很可能在处理完第一个“出牌”动作后，某个用于控制玩家操作的锁（例如服务端的 `_currentlyProcessingPlayerActionId` 或客户端的某个状态标志）没有被正确重置或释放，导致后续所有动作被阻塞。

## 2. 修复计划

将分两步进行：
1.  **分析问题一 (攻击主战者)**: 重点排查客户端 `src/gameManager.js` 中的 `selectAttackTarget` 函数，以及服务端 `Server/Services/GameService.cs` 中处理攻击请求和 `FindEntityByUid` 的相关逻辑。
2.  **分析问题二 (卡牌连打)**: 重点排查服务端 `Server/Services/GameService.cs` 中的 `GameProcessingLoopAsync` 方法，特别是关于动作队列处理和 `_currentlyProcessingPlayerActionId` 状态的清理逻辑。
