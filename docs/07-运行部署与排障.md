# 运行部署与排障

> 核对日期：2026-09-27。本文记录当前脚本与配置；本次整理没有执行部署、启动应用或数据库迁移。

## 构建不等于部署

```powershell
npm run build
dotnet publish "Server/ShadowverseBeyond.Server.csproj" -c Release -o "Server/publish"
```

前端构建输出为 `dist`。以上生成构建产物，不自动完成生产目录准备、身份边界检查、服务托管和联机验证。

[deploy.ps1](../deploy.ps1) 会构建前端，把入口复制为根目录 `index.prod.html`，更新根目录资源和 PWA 文件，再发布后端。它还会备份或替换资源目录、暂存并恢复 `assets/cards`。`-NoBackup` 分支包含删除操作；执行前应确认路径、业务资源和备份。

常见参数含 `-SkipFrontend`、`-SkipBackend`、`-SkipNpmInstall`、`-NoBackup`、`-StartServer`、`-SetProductionEnv`、`-CreateProdConfig`、`-Urls`、`-PublishDir`。不要把此脚本当作只读健康检查。

## 内容根目录是发布关键点

[Program.cs](../Server/Program.cs) 使用 `ContentRootPath` 的上一级定位前端；[DataSeeder](../Server/Infrastructure/Data/DataSeeder.cs) 也从其上一级的 `data` 读取数据。若直接在 `Server/publish` 内运行 DLL，默认内容根目录可能与源码运行时不同，前端和种子相对路径也随之改变。

启动前应明确：

1. 哪个目录是应用 `ContentRootPath`。
2. 其上一级是否包含预期的 `index.prod.html`、`assets` 和 `data`。
3. 哪个目录加载 `appsettings*.json`，相对 SQLite 路径最终指向哪里。
4. 静态文件中间件实际暴露哪些路径。

生产入口选择还受开发环境及前端模式配置影响，以 `Program.cs` 为准。部署后检查真实页面加载、API、WebSocket、资源和日志；仅看到 DLL 正在运行不足以判定部署成功。

## 回放：默认不会持续写 Journal

来源：[ReplayOptions](../Server/Options/ReplayOptions.cs)、[appsettings.json](../Server/appsettings.json)。

| 配置 | 代码默认值 | 含义 |
|---|---|---|
| `EnableJournalWrites` | `false` | 日志持久化写入开关 |
| `PersistClientDtos` | `false` | 是否持久化客户端 DTO |
| `EnableSnapshots` | `true` | 快照选项；仍需结合实际调用及 Journal 开关检查 |
| `CompressSnapshots` | `true` | 快照压缩 |
| `SnapshotOnGameStart/TurnStart/GameEnd` | `true` | 相关快照时机选项 |
| `SnapshotEveryBundles` | `0` | 按 bundle 周期生成快照的选项 |
| `RetentionDays` | `7` | 日志保留天数 |
| `CleanupIntervalMinutes` | `30` | 清理间隔 |
| `RequireJoinCodeForReplayReads` | `false` | 回放读取的加入码检查开关 |

表中是默认值，部署配置覆盖后可能不同。开启日志或 DTO 持久化会改变存储量和记录内容，调整前确认需求、访问边界和保留策略。

[ReplayController](../Server/Controllers/ReplayController.cs) 提供 `GET /api/replay/{gameId}/events`、`export`、`head`、`snapshot`、`enter`、`validate`。GameHub 有 `CatchUp`、`Seek`；接口存在不代表默认环境已有完整可回放记录。这里的 `gameId` 是单局标识。

- `dev-tools`：工具页；`dev-tools/match-lab`：对战实验室。
- `/loghub`：实时日志与快照，身份检查见 [LogStreamHub](../Server/Hubs/LogStreamHub.cs)。

## 常见症状的检查顺序

| 症状 | 先检查什么 |
|---|---|
| 页面打开但 API / Hub 失败 | 后端是否为 5100；Vite 代理；浏览器 Network；WebSocket 连接错误 |
| 服务启动但卡牌为空 | 迁移/种子异常日志、实际数据库、内容根目录上一级的 `data` |
| 发布后页面或资源 404 | 内容根目录、前端入口选择、静态资源和种子相对路径 |
| 保存能力后仍显示旧值 | 保存响应、数据修订头、服务端目录缓存、前端变更通知 |
| 回放为空 | 两个持久化开关、单局 ID、实际数据库和清理策略 |
| 联机动作找不到对局 | `RoomId` / `ActiveGameId` 是否混用，连接上下文与房间生命周期 |
| 任务完成但金币未到账 | 是否已领取、任务周期、去重记录与金币事务 |
| 表情目录为空 | `assets/emotes` 的包目录、支持的资源格式、缓存时效和静态访问路径 |

特别注意：`Program.cs` 捕获迁移/种子异常后记录日志，相关分支未强制退出。因此“进程活着”不是数据库初始化成功的证据。
