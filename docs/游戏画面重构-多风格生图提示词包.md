# 游戏画面完全重构：多风格成套美术探索任务提示词

> 本轮交付是提示词，尚未生成图片。以下为交给执行 Agent 的完整任务指令；执行时应将共享风格规范与每个界面的具体内容合并成独立的生图提示词，而不是把整份任务书发给模型要求绘制一张拼贴。

## 目标

担任本项目的游戏美术总监与 UI 概念设计师，参考 `D:/workspace/Shadowverse-Cloud-Beyond/docs/游戏界面功能地图.md`，为游戏进行全界面、多风格的美术探索，并调用生图模型产出成套参考图。

这是美术方向探索，不是现有界面换色，也不是代码重构。保留既有功能语义、信息优先级和操作关系；重新探索构图、布局、字体气质、材质、图标、卡牌框架、场景背景和视觉反馈。旧界面只提供功能依据，不限制新美术方向。文档未核实的细节应通过相关实现补核，不将推测当成现有功能。

目标体验：同一风格内，各界面像同一个游戏世界的连续切换；不同风格之间，则具有显著不同的美术性格。每张图既有游戏气质，也能看清真实功能结构。

## 探索方向

以下五种风格是本轮建议探索集，不代表用户已经选定方向。每种风格独立成批，所有批次使用相同界面清单和主要内容，便于公平比较。

### A. 星界航行
深靛蓝宇宙、冷青能量、少量紫色强调，精密蚀刻金属和半透明光学面板。以天文仪器、星图和航行系统建立独特图形语言。背景具有宇宙空间纵深，交互区域简洁清晰。避免依靠满屏发光边框制造科技感。

### B. 月辉圣典
月白、墨蓝、旧金，磨砂黑曜石、书页与雕刻金属。以星界圣堂、纹章、魔法书和月相建立视觉母题。标题优雅，卡牌精致，操作区域具有清晰留白。复杂装饰集中于品牌与关键边缘，编辑器和数据区域保持克制。

### C. 装甲竞技场
石墨黑、混凝土灰、氧化银与警示橙。以装甲切角、机械卡槽、编号与刻度建立图形语言，营造有重量的竞技设备体验。通过结构比例和材质而非杂乱工业纹理表达力量。战场像竞技装置，编辑器像专业装配台，但保持相同产品身份。

### D. 都市街机
午夜蓝与明亮的紫红、青绿、暖黄形成有节奏的色彩对比。亚克力、平面图形、贴纸标签和未来城市夜景结合，强调年轻、社交与快速对战。标题具有动势，信息区稳定，表现活跃而非满屏霓虹。建立独立的卡框、徽记和导航语言。

### E. 星象收藏馆
骨白、墨黑、铜色与深酒红，纸张、压印、细线网格和编辑式排版。以星象档案、收藏册和展陈空间建立游戏世界，依靠比例、留白和卡牌美术形成视觉焦点。安静但有幻想感与竞技张力，避免成为普通企业网站或办公后台。

## 每批固定页面清单

每批至少输出以下 9 张独立全屏图片。五个方向共 45 张核心界面图；“批次”指同一风格的交付集合，不要求在一次模型调用中完成。

| 编号 | 界面 | 图片必须表达的主要功能 |
|---|---|---|
| 01 | 主菜单/大厅 | 游戏品牌；单人模式、多人对战、卡牌工坊、牌组编辑、系统设置五个入口；用户、任务、关于入口 |
| 02 | 单人模式 | 人机/本地双人切换、玩家卡组、对手卡组、开始对战；地城解谜与剧情关卡明确为未开放 |
| 03 | 多人对战 | 当前卡组、创建房间、GameId/JoinCode 加入、观战入口及状态、进入对战 |
| 04 | 对战战场 | 双方头像、生命与资源、双方场地区域、玩家手牌、回合控制、选中卡牌预览、行动/目标指示 |
| 05 | 卡牌工坊 | 目录与搜索筛选、基础属性、能力编辑、素材管理、预览、保存，以及玩家设定入口 |
| 06 | 牌组编辑 | 卡组管理、卡牌目录与筛选、当前构筑与数量、费用曲线、环境/规则、校验、导入导出入口 |
| 07 | 系统设置/开发工具 | 日志、实验室、控制台、API 测试、数据库入口、用户管理、禁限卡牌、环境配置、胜率看板；权限区别 |
| 08 | DSL 编辑器 | 能力字段/结构化编辑、结构与效果预览、校验反馈、保存；勿将探索性的节点布局称为现有实现 |

一个界面可以用分页、页签和折叠区承载次要功能，避免将所有控件强塞在一屏。代表状态优先选择正常、有内容的状态。所有批次展示同等功能密度和相同对战阶段。

## 子界面与浮层覆盖

九个核心页面不是全部状态。执行前建立完整图片清单，将以下现有子界面逐项归属到父页面；各批次采用相同清单。每个下列子界面各补一张独立截图式参考图，保留可辨认的父页面背景，而非只画孤立弹窗：

- 用户资料；登录/注册；日常任务；关于与安装入口。
- 卡牌详情；卡组选择；观战房间选择；退出对战确认。
- 卡牌素材裁切；玩家设定；新建/导入卡组。
- 实时日志；开发者控制台；用户管理；禁限卡牌；环境卡包配置；胜率看板。

以上为 17 张补充图，与 9 张核心图合计每批 26 张，五批共 130 张计划图片。复合编辑状态和更多二级标签页先记录在清单中，不暗自扩展数量。补核后若某项实际不是独立界面，应说明合并依据并同步调整各批计数。加载、空态、错误、胜负结算等状态列入后续状态设计清单，本轮不要求每个页面重复绘制全部状态。

## 同批次一致性要求

每批先建立一份简短且具体的风格规范，锁定：

- 主题母题、色彩角色、材质与光照逻辑。
- 标题和正文的字体气质、文字层级。
- 按钮、页签、面板、弹窗、图标的形状和边框语言。
- 卡牌框架、费用/攻击/生命的表现方式、角色头像与徽记语言。
- 当前选中、可点击、不可用、成功、警告和错误的状态表达。
- 全局入口、页面标题、返回路径的连续性。

先生成本批主菜单作为风格锚点，检查方向成立后再生成战场与牌组编辑，检验其对战斗和高信息密度页面的适应性；随后完成该批所有图片。其余风格重复相同步骤。锚点顺序用于提高一致性，不以只交付首页取代完整批次。

后续生成应实际传入本批锚点图片作为视觉参考。提示词明确指出：参考图用于共享材质、色彩、组件语言及品牌身份；当前图根据本页任务重新安排布局。涉及卡牌时，可附上本批已接受的战场或卡牌预览作为卡框参考。不同风格间不混用样式参考。

统一风格不等于机械复用同一种三栏布局：大厅负责吸引与导航，战场负责战术判断，编辑器负责长时间阅读和操作，管理页面负责数据扫描。它们拥有相同视觉语言，但构图应服务不同用途。

## 单张图的生成要求

每次生成只要求一张完整、正视、横屏的游戏界面概念图，不是网页宣传海报、设备样机或多界面拼贴。默认统一采用 16:9 桌面比例，使用模型实际支持的最接近尺寸并记录调整。

以游戏“星云”的现有品牌语义为依据，主标题可使用现有“SHADOWVERSE / WORLD BEYOND”；不将第三方现有品牌宣称为本项目原创。各批次保持相同标题内容。

关键导航和操作优先使用简短中文，并在单张提示词中给出准确文字。密集长文只表达合理的信息密度；检查中文字形和可读性，记录残留缺陷。无需为概念图复写完整规则或长日志。展示用数值应保持逻辑一致，并在交付说明中标记为视觉示例，不声称来自真实游戏数据。

背景、卡牌插画与装饰需要表现风格，但优先保护牌面、资源、当前行动和主要按钮的可读性。对战图展示有代表性的稳定回合状态，少量目标高亮即可，避免用全屏特效掩盖布局。

旧界面截图若作为参考，只承担功能、信息和关系参考；明确允许重新设计视觉与布局。没有截图时以经核对的功能摘要为依据，不声称已经完成截图比对。

静态参考图可以暗示切换与反馈的视觉效果；真实动画节奏单独用说明表达，不把静态图描述成已实现动效。

## 执行与交付

1. 核对功能地图，形成各批完全一致的编号清单。
2. 为每种方向写出简短风格规范，并将其与当前页面功能合成为完整的单图提示词；交给模型前展开所有引用，不发送未替换的占位符。
3. 按锚点到完整系列的顺序实际生成；逐张检查功能、风格和可读性，针对明显偏离做定向修正。
4. 每种风格独立目录，文件名包含风格、编号和页面名。原始单图独立保存；比较总览由已生成图片另外排版，不取代单图。
5. 交付图片索引、各风格简介、共享风格规范、实际提示词、实际模型与输出尺寸、完成数量及遗留缺陷。
6. 按系列一致性、风格差异、功能可识别性、战场可读性、编辑器使用效率和实现可行性评价。特别检查是否只是换色，是否普通后台模板化，是否首页漂亮但其他页面风格崩溃。

本阶段止于美术探索与方向比较，不修改游戏源码，不新增玩法，不将概念图当作已经实现的游戏界面。后续再依据选择的方向细化设计规范与实际重构。
