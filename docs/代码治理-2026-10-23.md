### 技术栈与工程入口

- 前端是原生 JavaScript ESM、HTML/CSS，不是 React/Vue。运行依赖包括 SignalR；构建实际解析为 Vite 6.4.1，测试为 Jest 30.2.0、jsdom、Babel。
- 后端是 C# / ASP.NET Core net8.0，EF Core SQLite、AutoMapper、Scrutor、Serilog、ImageSharp。测试为 xUnit、Moq、EF InMemory。
- 根 global.json 指定 SDK 8.0.413；本机实际解析为 8.0.426。Node 24.19.0、npm 11.17.0、Python 3.13.3。
- 实际项目为 Server/ShadowverseBeyond.Server.csproj 与 Server.Tests/ShadowverseBeyond.Server.Tests.csproj，均在根解决方案内。
- 静态导入图覆盖 106 个前端生产 JS 文件；另有 21 处字面量动态导入。后端生产 C# 文件共 741 个，包含迁移与 DTO，不把生成文件数量当作业务复杂度。
- 前端测试位于 tests、src/__tests__，后端位于 Server.Tests。未发现 .github/workflows；安装 Playwright 不代表已有统一浏览器验收入口。
- 后端启动会迁移和填充数据库，本轮未为冒烟而启动真实数据库，也未运行部署脚本。

### 状态、生命周期与错误路径

- 服务器负责规则；前端提示与可玩性缓存不应成为规则真值。GameService 是单例，事务服务按作用域创建，动作按单局排队。
- 数据目录通过数据库、GameDataProvider、X-Data-Revision 与浏览器失效事件传播。浏览器目录数组和索引必须在同一次发布中保持一致。
- main.js 持有可替换的 SignalR 连接；开发控制台反向导入启动入口，形成初始化耦合。
- GameContext 使用环境上下文与 Dispose；嵌套作用域、record 复制和异步传播需要专门契约，不能仅靠空值兜底修改。
- CardSnapshotCapture.TryCapture 捕获所有异常并返回空；快照构建还依赖卡牌有效关键字。两者与既有快照/事务失败有关联，但尚未证明共同根因，暂不修改。
