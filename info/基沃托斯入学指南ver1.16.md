## 1 简介

### 1.1 CSV文件简介

在游戏中，卡牌数据存储在数据表中。要自定义卡牌，需要编辑以下 CSV文件：

*   **卡片信息 (`info.csv`)**：存储卡牌的基本信息，如编号、名称、属性等。
*   **卡片效果 (`effect.csv`)**：定义卡牌的效果、参数及其触发条件。
*   **卡片描述 (`description.csv`)**：`info.csv` 的附加文件，包含卡牌的描述文本。
*   **卡片增益 (`buff.csv`)**：定义额外效果的参数、结束条件和附加能力。
*   **卡片计数器 (`stats.csv`)**：定义游戏进程中需要使用计数器的各项参数。

这些文件通常位于游戏Data路径的 `Assets\StreamingAssets\Cards` 目录下，以D盘为例，如：

*   `D:\SV CLOUD\Shadowverse Cloud_Data\StreamingAssets\Cards\info.csv`
*   `D:\SV CLOUD\Shadowverse Cloud_Data\StreamingAssets\Cards\effect.csv`
*   `D:\SV CLOUD\Shadowverse Cloud_Data\StreamingAssets\Cards\description.csv`
*   `D:\SV CLOUD\Shadowverse Cloud_Data\StreamingAssets\Cards\buff.csv`
*   `D:\SV CLOUD\Shadowverse Cloud_Data\StreamingAssets\Cards\stats.csv`

### 1.2 编辑CSV文件

可以使用任何文本编辑器（如Notepad++、VSCode）或电子表格软件（Excel）编辑。在编辑时，请遵循以下准则以确保数据的正确性：

1.  **备份文件**：在进行任何修改之前，先备份原始CSV文件，以防需要恢复。
2.  **维持结构**：CSV文件的每一行代表一条记录，每个值由逗号分隔。确保不要改变列的顺序或添加新列。
3.  **正确输入**：确保输入的数据符合游戏的规则和逻辑。例如，属性值应该是数字，效果触发条件需要正确编写，大部分字段为空的情况下请填写 `none`。
4.  **保存更改**：编辑完成后，保存文件。如果使用的是电子表格软件，请确保以CSV格式保存。

### 1.3 应用更改

编辑和保存CSV文件后，更改将在下一次启动游戏时生效。如果游戏已经运行，需要重启游戏以加载新的数据。

## 2 创建卡片

### 2.1 基本信息

`info.csv` 包含卡片的基本属性信息，简单说明如下：

| 列名    | 说明     | 连接符 | 空值   | 注释                 | 参考值                                                                 |
| :------ | :------- | :----- | :----- | :------------------- | :--------------------------------------------------------------------- |
| id      | 编号     | 无     | 无     | 卡片的唯一标识符     | `110001202`                                                            |
| name    | 名称     | 无     | 无     | 卡片名称             | `名字很长能不能把表格撑的很开那样的话应该会很好看吧`                     |
| status  | 属性     | 无     | 无     | 输入格式为 消费/攻击力/生命值 | `2/2/2`                                                                |
| trait   | 类型     | /      | none   | 类型一览详见附录     | `2/3`                                                                  |
| keyword | 关键字   | /      | none   | 关键字一览详见附录   | `4`                                                                    |
| option  | 选项     | &      | none   | 卡片额外选项         | `countdown=1`                                                          |
| effect  | 效果     | /      | none   | 卡片效果id           | `名字长：很短` (这个参考值似乎有误，应为效果ID，如 `119900001`) |

#### 2.1.1 编号

卡片的id是一个9位数字，其中每一位都包含了该卡片的信息，生成后应保持固定不变。

*   **组别** → `0`00000000
    *   一般卡片为1，特殊卡为5，结晶为7，激奏为8，衍生物为9。
*   **分区** → 0`0`0000000
    *   默认情况下填写为1，官方卡包为0。
*   **卡包** → 00`000`0000
*   **职业** → 00000`0`000
    *   中立、妖精、皇家、巫师、龙族、死灵、血鬼、主教、复仇者依次为0~8。
*   **罕度** → 000000`0`00
    *   铜、银、金、传说依次为1、2、3、4。
*   **种类** → 0000000`0`0
    *   随从卡、法术卡、护符卡依次为1、2、3。进化后的随从卡为9。主战者为0。
*   **序号** → 00000000`0`

#### 2.1.2 选项

卡片的`option`包含了一些未在表格中出现的设置选项，包括：

*   `nameId=000000000` - 当填写该选项时，该卡片将被视为指定ID卡片的同名牌。
*   `artId=000000000` - 当填写该选项时，该卡片将改为加载指定ID卡片的图片资源。
*   `countdown=00` - 当填写该选项时，卡片的倒数将被设置为指定数值。需要提前确认卡片是否拥有倒数关键字。
*   `charge=00` - 当填写该选项时，卡片的蓄积将被设置为指定数值。需要提前确认卡片是否拥有土之印类型和蓄积关键字。

#### 2.1.3 范例

| id        | name     | status | trait | keyword | option      | effect |
| :-------- | :------- | :----- | :---- | :------ | :---------- | :----- |
| 119904101 | 魔法芝士 | 1/20/1 | none  | 1       | none        | none   |
| 111222333 | 灌饼     | 0/0/0  | 1/2   | 7       | countdown=99 | none   |
| 119904901 | 魔法芝士 | 1/1/20 | none  | 2       | none        | none   |

以上是三组测试数据。其中：

*   **魔法芝士** 是一张来自于第99个卡包的中立传说随从卡，它的消费为1，攻击力为20，生命值为1。它具有疾驰能力。
*   **灌饼** 是一张来自于第12个卡包的皇家金色护符卡。它的消费为0，具有士兵和指挥官两个类别，并且拥有倒数能力，倒数值为99。
*   **第二张魔法芝士** 是前者的进化。进化之后，它的攻击力转变为1，而生命值转变为20，并且具有的能力从疾驰改为了守护。

### 2.2 描述

`description.csv` 存储了卡片在游戏中显示的文本，简单说明如下：

| 列名        | 说明   | 注释                               | 参考值                               |
| :---------- | :----- | :--------------------------------- | :----------------------------------- |
| id          | 编号   | 卡片的唯一标识符，与card的id对应 | `110001202`                          |
| name        | 卡名   | 卡片名称，仅用于查阅               | `短`                                 |
| description | 描述   | 卡片的描述，具有换行和显示黄字的功能 | `[1]|[101] 召唤1个[910104301]到战场上` |

描述的修改不会对卡片效果造成实际影响。在输入特殊符号时，将改变文本的读取方式：

*   `|` - 转换为换行符
*   `[000000000]` - 转换为此id对应的卡片名称
*   `[000]` - 转换为此id对应的关键字名称
*   `[]` - 其他情况下，高亮显示框选文字

## 3 增加卡片效果

### 3.1 基本信息

`effect.csv` 包含卡片效果的信息，简单说明如下：

| 列名      | 说明     | 连接符 | 空值   | 注释                                       | 参考值                               |
| :-------- | :------- | :----- | :----- | :----------------------------------------- | :----------------------------------- |
| id        | 编号     | 无     | 无     | 唯一标识符                                 | `119900001`                          |
| name      | 名称     | 无     | 无     | 效果名称，在效果的effect栏中引用           | `双倍天使之箭`                       |
| timing    | 时点     | 无     | none   | 效果的触发时机                             | `on_this_play`                       |
| place     | 区域     | 无     | none   | 效果的触发区域                             | `hand`                               |
| target    | 目标     | \_     | none   | 效果的目标对象                             | `op_field_0_all`                     |
| keyword   | 关键字   | /      | none   | 效果的能力关键字                           | `102/110`                            |
| stats     | 计数     | /      | none   | 效果所引用的计数器                         | `combo`                              |
| condition | 条件     | &      | none   | 触发效果实际需要满足的条件；详见后文       | `me.isMyTurn=1&effect.source.where=5` |
| ability   | 能力     | 无     | 无     | 效果的能力类型                             | `damage`                             |
| option    | 选项     | &      | 无     | 能力的具体参数                             | `damage=2`                           |

#### 3.1.1 编号

效果的id是一个9位数字，其中，前5位（即组别、分区、卡包和职业）与卡片id的生成规则一致，最后4位作为效果的序列号。

#### 3.1.2 区域

`place` 决定了效果能够在哪个区域触发。注意，即使效果已经满足条件，如果卡片的位置在其他效果的执行过程中发生了改变，该效果依旧不会执行。当需要创建执行过程可能会导致卡片位置改变的效果时（如入场曲能力），请填写为`none`。

#### 3.1.3 时点

`timing` 的语法由 `阶段_（目标_）行动` 构成。其中，每一部分有数个可选项，具体见下：

*   **阶段** →
    *   `on` – 在行动发生时触发（常用）
    *   `before` – 在行动之前触发。使用该时点可能会改变后续效果的执行结果。
    *   `after` – 在行动结束之后触发。使用该时点时效果的条件会在执行时判断。
*   **目标** →
    *   `this` – 在动作来源为这张卡片时触发
    *   `other` – 在动作来源为其他卡片时触发
*   **动作** →
    *   `turn_start` – 回合开始
    *   `turn_end` – 回合结束
    *   `play` – 使用卡片
    *   `draw` – 抽取卡片
    *   `summon` – 召唤卡片
    *   `attack` – 随从攻击
    *   `defense` – 随从被攻击
    *   `fight` – 随从交战
    *   `evolve` – 随从进化（该效果需要附加在进化后的随从上）
    *   `evolve_with_ep` – 随从手动进化（该效果需要附加在进化后的随从上）
    *   `destroy` – 破坏
    *   `vanish` – 消失
    *   `return` – 回手
    *   `leavefield` – 离开战场
    *   `buff` – 获得属性增益
    *   `debuff` – 获得属性减益
    *   `damage` – 受到伤害
    *   `heal` – 受到回复
    *   `flag_change*` – 玩家状态发生变化(flag为对应的状态名，如复仇对应venge)
    *   `ability*` – 当特定能力的效果发动（ability为对应的效果能力名）
    *   `keyword*` – 当特定关键字的效果发动（keyword为对应的效果关键字名）

举例而言，一个基础的时点为`on_play`，这是`timing`必要的基本组成部分，代表了在玩家使用一张卡片的时候触发。在其中加入目标可以将其变为`on_this_play`或`on_other_play`，该效果将在使用这张卡片或使用其他卡片时触发。

#### 3.1.4 目标

`target` 的语法由 `玩家_区域_数量_模式（_筛选）` 组成，简单介绍如下：

*   **玩家** →
    *   `me` – 我方
    *   `op` – 敌方
    *   `all` – 全部
    *   `sourceEffect.source` – 来源效果的来源卡片
    *   `sourceEffect.target` – 来源效果的目标卡片
    *   `sourceEffect.me` – 来源效果的我方目标卡片
    *   `sourceEffect.op` – 来源效果的敌方目标卡片
*   **区域** → 所有区域参数均可使用`+`号连接使用
    *   `deck` – 卡堆
    *   `hand` – 手牌
    *   `leader` – 主战者
    *   `field` – 战场
    *   `grave` – 墓地
    *   `token` – 衍生卡（选择）
*   **数量** → 可选目标的数量
*   **模式** →
    *   `all` – 全选
    *   `random` – 随机
    *   `first` – 依序选择
    *   `index` – 指定目标
    *   `noindex` – 除指定目标以外全选
    *   `other*` – 除本卡片之外；在其他选项之后使用`+`号连接使用

卡片筛选是以多个`[...]`构成的条件。根据语法，游戏将从所有待选目标找出符合条件的卡片，该功能的使用方式将在后文章节中单独说明。

**特殊选项：** 当使用`self`作为`target`时，使用本卡片作为目标，无须填写其他内容。

#### 3.1.5 关键字

与卡片的关键字不同，能力的关键字本身不会产生实际上的游戏效果。它的作用为满足卡片筛选的条件，以及在执行效果时创建一个同名的时点。例如，当执行入场曲（Fanfare）效果时，所有时点为`on_fanfare`的效果将可以触发。

#### 3.1.6 条件

`condition` 的作用为获取游戏中的相关计数器数值，如无必要可以不进行填写。例如，当填写为`combo`时，卡片描述中将会显示当前的连击数。

与之相对，`cond_option`用于保存效果需要触发时实际检测的条件。`cond_option`是由多个比较构成的复合表达式，以`&`对每个条件进行分割，其组成较为复杂，将在后续章节详述。

#### 3.1.7 能力

`ability` 用于定义effect具体产生何种效果。根据`ability`的类型需要不同的参数设置，将填写在`ability_option`中。

### 3.2 能力一览

本节将介绍`ability`及其相关`ability_option`的填写方式，模版和共用输入/输出项如下：

（能力概述）

*   **（共用）who = me/op**
    *   默认为`me`。决定由哪一方发动能力。
*   **（共用）hide = true/false**
    *   默认为`false`。决定是否显示战斗记录。
*   **（共用）repeat= num**
    *   默认为`1`。能力触发后的结算次数。
*   **（共用）appendix = effectid**

## 6 处理卡片逻辑

### 6.1 表达式

在效果与状态的配置文件中，通常需要使用到表达式的解析规则，它们形如`me.leader.combo>=4`（连击数为4以上）或`damage=effect.source.boost`（伤害等于该卡片的魔力增幅）。这些表达式的作用是获取当前游戏系统中变量作为数值（回答为YES或NO的情况下，一般认为YES=1/NO=0）并进行操作。在`cond_option`中，它们用于通过操作符进行比较来判断当前情况是否满足条件；在`ability_option`中，它们用于代替数字输入，使卡片的效果能随游戏状态发生改变。

一个表达式通常由它的左侧元素、右侧元素和操作符组成，其中每个元素都可以是一个更小的表达式。对于最终执行的表达式元素来说，每一个由`.`分割的部分都代表游戏中一个层面的信息，后者归属于前者，这些用于表示信息的字符被称作标识符。因此，创建一个表达式实际上是从能力的默认状态开始，自上而下的逐步获取当前游戏状态，并进行数值计算/比较的过程。

### 6.2 操作符

#### 6.2.1 比较操作符

比较操作符在执行成功后会返回一个YES或NO的结果，该结果将表明表达式条件是否已经满足。一般仅用于`cond_option`和卡片筛选。常见的比较操作符如下：

-   小于 (`<`)
-   大于 (`>`)
-   等于 (`=`)
-   小于等于 (`<=`)
-   大于等于 (`>=`)
-   不等于 (`!=`)

#### 6.2.2 计算操作符

计算操作符在执行成功后会返回一个数值结果，该数值结果可以继续用于计算或比较。注意，表达式的解析会从左到右执行，因此数学中混合算式的运算规则不适用于表达式的计算，填写时需要注意运算顺序。常见的计算操作符如下：

-   相加 (`+`)
-   相减 (`-`)
-   相乘 (`*`)
-   相除 (`/`)
-   取余 (`%`)
-   取较小值 (`><`)
-   取较大值 (`<>`)
-   取区间内随机值 (`~`)

### 6.3 标识符

#### 6.3.1 默认

-   `me.` - 转到我方玩家
-   `op.` - 转到敌方玩家
-   `sourceEffect.` - 转到来源效果
-   `effect.` - 转到本效果
-   `sourceBuff.` - 转到来源状态

-   `isMyTurn` - 是否为该玩家的回合
-   `isDone` - 是否已结束回合
-   `isAwake` - 觉醒发动
-   `isVenge` - 复仇发动
-   `isEager` - 渴望发动
-   `isReson` - 共鸣发动
-   `isIntro` - 间奏发动
-   `deck.` - 转到牌堆区域
-   `hand.` - 转到手牌区域
-   `field.` - 转到战场区域
-   `grave.` - 转到墓地区域
-   `leader.` - 转到主战者

#### 6.3.3 区域(deck/hand/lfield/grave)

-   `count` - 区域内卡片数量
-   `maxCount` - 区域内最大卡片数量
-   `availableCount` - 区域内剩余可用卡片位
-   `isFull` - 是否达到上限
-   `(grave)graveCount` - 当前墓地数量
-   `list.` - 以区域内卡片转到卡片列表
-   `list[...].` - 以区域内卡片批量筛选后的结果转到卡片列表

#### 6.3.4 主战者(leader)

-   `craft` - 职业
-   `hp` - 当前生命
-   `hpMax` - 最大生命
-   `hpInit` - 初始生命
-   `pp` - 当前能量点
-   `ppMax` - 最大能量点
-   `ep` - 当前进化点
-   `epMax` - 最大进化点
-   `isEpUsed` - 本回合是否已使用进化点
-   `combo` - 本回合使用卡片数
-   `rally` - 协作数

#### 6.3.5 效果(effect/sourceEffect)

-   `useTimes` - 效果触发次数
-   `turnUseTimes` - 本回合效果触发次数
-   `maxUseTimes` - 最大效果触发次数
-   `source.` - 转到该效果所属卡片
-   `sourceBuff.` - 转到该效果所属状态
-   `(sourceEffect)target.` -以所有目标卡片转到卡片列表
-   `(sourceEffect)target[...].` -以目标卡片批量筛选后的结果转到卡片列表

#### 6.3.6 列表(list)

-   `count` - 列表内卡片数量
-   `list[...].` - 以列表卡片批量筛选后的结果转到卡片列表
-   `card[num].` - 转到按顺序排列的第num-1张卡片

#### 6.3.7 卡片(source/card)

-   `uid` - 该卡片的原始id
-   `id` - 该卡片的名称id
-   `group` - 该卡片的组别（返回值参见卡片编号，以下亦同）
-   `zone` - 该卡片的分区
-   `pack` - 该卡片的卡包
-   `type` - 该卡片的类型
-   `rarity` - 该卡片的罕度
-   `serial` - 该卡片的序列号
-   `cost` - 该卡片的消费
-   `atk` - 该卡片的攻击力
-   `hp` - 该卡片的当前生命值
-   `hpMax` - 该卡片的最大生命值
-   `count` - 该卡片的倒数
-   `isAttacked` - 该卡片是否已攻击
-   `where` - 该卡片目前的游戏区域（牌堆、手牌、主战者、战场、墓地依次为1~5）
-   `(source)isMe` - 该卡片是否属于我方
-   `(source)isOp` - 该卡片是否属于敌方
-   `filter [...]` - 该卡片是否能够通过条件的单独筛选
-   `...` - 其它自定义数值型参数（`...`为参数的名称，通过`SetValue`效果或`Stats`类增加）
-   `...?value` - 其他自定义字符型参数是否为`value`（`...`为参数的名称）
-   `base.` - 转到该卡片的基本卡片
-   `evolve.` - 转到该卡片的进化卡片（若有的话）
-   `current.` - 转到该卡片的当前卡片
-   `origin.` - 转到该卡片的初始卡片（基本或进化）

#### 6.3.8 状态(sourceBuff)

-   `cost` - 该状态增加的消费（可以为负数）
-   `atk` - 该状态增加的攻击力（可以为负数）
-   `hp` - 该状态增加的生命值（可以为负数）
-   `source.` - 转到该状态所属的卡片
-   `sourceEffect.` - 转到该状态的来源效果

## 7 卡片筛选

### 7.1 简介

卡片筛选是一种特殊的表达式语法，当使用筛选器时，需要使用`[]`转换特定筛选条件。例如：

-   `target - op_field_1_index_[type:1|9]`
-   `cond_option - me.field.list[keyword:5].count>0`
-   `ability_option - filter=[craft:me.leader.craft][rarity:3|4]`

可以看出，卡片筛选的基本格式为`[类型1:参数1|参数2...][类型2:参数3...]`。

对于同一个条件中的多个参数，只需要满足任意一个参数的条件即可。

-   当使用`filter[cost:1|9]`时，所有消费为1或9的卡片均能够通过筛选。

如果希望只有同时满足同一类型多个参数的卡片成为筛选结果，可以多次使用同一类型的查询。

-   当使用`filter[trait:1][trait:2]`时，同时具有指挥官和士兵种类的卡片能够通过筛选。

对于数值类的筛选，可以使用比较操作符增加筛选范围。

-   当使用`filter[atk:<=5] [atk:>2]`时，所有攻击力小于等于5且大于2的卡片能够通过筛选。

当对于卡片本来就可能有多个的条件使用筛选时，使用`!`可以使检测包含变为检测为不包含。

-   当使用`filter[keyword:!4]`时，所有不具有疾驰的卡片能够通过筛选。

### 7.2 单独筛选

单独筛选通常接受一组参数，并根据这些参数判断卡片是否满足条件，并最终返回1(Yes)或0(No)作为结果。当对于复数卡片使用单独筛选时，会依次检测卡片列表中的每一张卡片是否满足条件，并返回所有通过筛选的卡片。常见的单独筛选如下：

-   `format` - 卡片是否为指定模式
-   `zone` - 卡片的区域
-   `name` - 卡片的名称是否包含参数
-   `description` - 卡片的描述是否包含参数
-   `uid` - 卡片的原始id
-   `id` - 卡片的名称id
-   `group` - 卡片的组别（返回值参见卡片编号，以下亦同）
-   `craft` - 卡片的职业
-   `pack` - 卡片的卡包
-   `type` - 卡片的类型
-   `rarity` - 卡片的罕度
-   `trait` - 卡片的种类是否包含参数
-   `keyword` - 卡片的关键字是否包含参数
-   `battleKeyword` - 卡片实际拥有的关键字是否包含参数
-   `cost` - 卡片的消费
-   `atk` - 卡片的攻击力
-   `hp` - 卡片的（当前）生命值
-   `countdown` - 卡片的倒数
-   `isattacked` - 卡片是否已攻击
-   `originCost` - 卡片的原始消费
-   `originAtk` - 卡片的原始攻击力
-   `originHp` - 卡片的原始生命值
-   `...` - 卡片的计数器（`...`为计数的名称，需要已通过Stats注册）

### 7.3 批量筛选

批量筛选通常接受一个参数，并根据此参数对列表进行操作，并最终返回一个新的列表。只有当筛选的卡片为复数时，批量筛选才是有意义的。常见的批量筛选如下：

-   `first` - 顺序从卡片列表中返回X张卡片
-   `last` - 逆序从卡片列表中返回X张卡片
-   `random` - 随机从卡片列表中返回X张卡片
-   `costOrder` - 将卡片列表依消费升序或降序排列。1为升序，-1为降序。
-   `atkOrder` - 将卡片列表依攻击升序或降序排列。1为升序，-1为降序。
-   `hpOrder` - 将卡片列表依生命升序或降序排列。1为升序，-1为降序。
-   `distinct` - 随机返回列表中X张不同名的卡片。
-   `costDistinct` - 随机返回列表中X张消费不同的卡片。
-   `atkDistinct` - 随机返回列表中X张攻击不同的卡片。
-   `hpDistinct` - 随机返回列表中X张生命不同的卡片。
