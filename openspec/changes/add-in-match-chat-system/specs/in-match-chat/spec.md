## ADDED Requirements
### Requirement: 房间级实时聊天
系统 MUST 提供房间级聊天通道；同一 `GameId` 下的双方玩家与观战者可实时接收聊天消息。聊天广播 MUST 仅限当前房间，不得泄漏到其他房间。

#### Scenario: 玩家发送消息并房间内广播
- **WHEN** 玩家在房间内发送一条合法聊天消息
- **THEN** 该消息被广播给该 `GameId` 房间内的所有在线参与者（玩家与观战者）

#### Scenario: 房间隔离
- **WHEN** `GameA` 房间中有人发送聊天消息
- **THEN** `GameB` 房间的连接不会收到该消息

### Requirement: 参与者权限与身份标注
系统 MUST 仅允许已通过现有连接校验的参与者发送聊天消息，并在消息中携带发送者类型（玩家/观战者）与展示名。

#### Scenario: 未通过校验的连接发送聊天
- **WHEN** 未完成房间校验的连接调用发送聊天
- **THEN** 服务端拒绝请求并返回可理解的错误信息

#### Scenario: 观战者发送聊天
- **WHEN** 合法观战连接发送聊天消息
- **THEN** 消息以“观战者”身份被广播到同房间

### Requirement: 消息校验与安全渲染
系统 MUST 对聊天内容进行服务端校验与清洗（空消息拒绝、长度限制、控制字符处理）。前端 MUST 以纯文本渲染消息内容，禁止把消息内容作为 HTML 注入。

#### Scenario: 空消息或超长消息
- **WHEN** 发送空白消息或超过长度上限的消息
- **THEN** 服务端拒绝发送并返回校验失败原因

#### Scenario: 含特殊字符消息渲染
- **WHEN** 消息包含 HTML 片段或脚本相关字符
- **THEN** 前端只显示其文本，不执行任何脚本

### Requirement: 聊天历史同步
系统 MUST 在连接加入房间后下发最近聊天历史（有界条数），用于新加入与重连时恢复上下文。

#### Scenario: 新连接加入房间
- **WHEN** 玩家或观战者成功加入房间
- **THEN** 客户端收到该房间最近 N 条聊天历史并按时间顺序展示

### Requirement: 发送频率限制
系统 MUST 对聊天发送频率实施基础限流，防止刷屏影响对战通信。

#### Scenario: 高频发送触发限流
- **WHEN** 同一参与者在短时间内连续发送超过阈值
- **THEN** 超额请求被拒绝，并返回“发送过于频繁”类错误

### Requirement: 顶部弹幕一次性播报
系统 MUST 在客户端收到实时聊天消息后，在对战界面顶部播放一次弹幕动画。弹幕 MUST 从左到右滚动，并在动画结束后自动移除，不影响聊天列表的完整展示。

#### Scenario: 聊天消息触发顶部弹幕
- **WHEN** 客户端收到房间实时聊天消息事件
- **THEN** 该消息在对战界面顶部从左到右滚动一次并消失

#### Scenario: 多条消息顺序播放
- **WHEN** 客户端在短时间内连续收到多条聊天消息
- **THEN** 消息按接收顺序依次播放顶部弹幕，不发生重叠覆盖

#### Scenario: 非对战页面不播放弹幕
- **WHEN** 用户已离开对战页面
- **THEN** 客户端不会显示聊天弹幕，且已存在弹幕队列会被清理
