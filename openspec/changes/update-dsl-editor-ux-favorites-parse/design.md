## Context
现有 DslEditor 以虚拟根 + 编辑路径统一编辑模型，但中文显示、点击编辑范围、类型提示上下文仍有缺口。新增“用户收藏”与“表达式反向解析”需要在前后端建立可复用的数据与解析通路。

## Goals / Non-Goals
- Goals:
  - 任意子表达式可点击进入编辑，工作区与编辑路径准确同步。
  - 中文可读化统一使用 displayName，隐藏 DSL 语法细节。
  - 胶囊 √/× 类型提示覆盖所有封装层。
  - 收藏表达式可检索、插入、统计使用频率。
  - 既有 DSL 可反向解析为可编辑 UI AST。
- Non-Goals:
  - 扩展 DSL 语法本身。
  - 改造 DSL 运行时执行器。

## Decisions
- 反向解析采用“后端解析服务 + 前端 AST 映射”方案，复用现有 C# Parser 保证语义一致性。
- 收藏表达式采用持久化表 + REST API，实现跨设备/账户同步。
- 前端对解析失败的表达式降级为 rawText，仍可被用户覆盖编辑。

## Alternatives considered
- 前端自研 Parser：实现快但维护成本高、语法漂移风险大。
- 仅本地收藏（localStorage）：无法跨设备同步，后续迁移成本更高。

## Risks / Trade-offs
- 解析 AST 与前端 UI AST 映射存在结构差异，需要定义稳定的 DTO。
- 收藏查询的性能随数据量增长，需要分页与去抖。

## Migration Plan
- 新增收藏表与 API，不影响现有能力编辑流程。
- 反向解析接口为可选增强，前端保留 rawText 降级路径。

## Open Questions
- 收藏的共享范围：仅个人、同项目内共享、还是全局共享？
- 反向解析 AST DTO 是否需要版本号以支持未来语法演进？
