# Change: Update Chained Ability Timing

## Why
Chained abilities currently trigger immediately after effect execution, before the effect's generated events are committed. This causes chained logic to miss final results (e.g., DrawEvent targets resolved during Commit). We need chained abilities to depend on committed outcomes.

## What Changes
- Execute chained abilities only after all events generated by an effect have been processed and committed.
- Move FailureHandling evaluation to after generated events are processed; treat generated-event commit failures as effect failures.
- Gate chained-ability execution based on the final effect outcome (success/failure).

## Impact
- Affected specs: effect-chaining (new)
- Affected code: Server/Services/GameActionTransactionService.cs (ProcessEffectAsync, ProcessChainedAbilitiesAsync)
- Behavior changes: chained ability timing relative to generated event processing and Commit
