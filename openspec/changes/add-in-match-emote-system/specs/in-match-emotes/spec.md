## ADDED Requirements

### Requirement: 表情清单按固定目录自动分组
系统 MUST 从固定表情根目录读取表情清单，并将一级子文件夹自动映射为表情分组。系统 MUST 只返回包含受支持图片文件的非空分组。

#### Scenario: 表情文件夹生成分组
- **GIVEN** 固定表情根目录下存在 `default/smile.png` 和 `line/hello.webp`
- **WHEN** 客户端请求表情清单
- **THEN** 系统返回 `default` 和 `line` 两个表情分组
- **AND** 每个分组包含其文件夹内对应的表情项

#### Scenario: 空分组和根目录散落文件被忽略
- **GIVEN** 固定表情根目录下存在空文件夹和根目录散落图片文件
- **WHEN** 客户端请求表情清单
- **THEN** 系统不会返回空文件夹分组
- **AND** 系统不会把根目录散落图片作为表情项返回

### Requirement: 表情清单只暴露安全元数据
系统 MUST 为每个表情项返回稳定 ID、分组 ID、展示名和静态资源 URL。系统 MUST NOT 在清单接口中返回物理磁盘路径、图片二进制内容或 base64 内容。

#### Scenario: 清单返回元数据而非图片内容
- **WHEN** 客户端请求表情清单
- **THEN** 每个表情项包含 `id`、`packId`、`name` 和 `url`
- **AND** 响应不包含本地磁盘绝对路径
- **AND** 响应不包含图片二进制或 base64 数据

#### Scenario: 表情 URL 指向静态资源路径
- **GIVEN** 表情项 ID 为 `default/smile.png`
- **WHEN** 系统返回该表情项
- **THEN** 表情项 URL 指向对应的静态资源路径
- **AND** 浏览器可通过该 URL 加载图片资源

### Requirement: 表情目录扫描必须限制文件类型和路径范围
系统 MUST 只接受白名单图片扩展名作为表情资源，并 MUST 防止路径穿越、绝对路径和任意 URL 被解析为表情资源。

#### Scenario: 不支持的文件类型被过滤
- **GIVEN** 表情分组目录中存在 `readme.txt`、`script.js` 和 `smile.png`
- **WHEN** 系统扫描表情目录
- **THEN** 清单只包含 `smile.png`
- **AND** 不返回不支持扩展名的文件

#### Scenario: 非法表情 ID 被拒绝
- **WHEN** 客户端提交包含 `../`、反斜杠、绝对路径或 URL 的表情 ID
- **THEN** 服务端拒绝该表情发送请求
- **AND** 不会解析固定表情根目录之外的文件

### Requirement: 表情消息必须复用房间聊天广播
系统 MUST 允许已通过现有房间连接校验的玩家和观战者发送表情消息。表情消息 MUST 广播给同一房间内的在线参与者，并 MUST NOT 泄漏到其他房间。

#### Scenario: 玩家发送表情并广播到当前房间
- **GIVEN** 玩家已在房间内连接
- **WHEN** 玩家发送一个存在于表情清单中的表情 ID
- **THEN** 系统向当前房间内所有在线玩家和观战者广播一条表情消息
- **AND** 广播消息包含表情 ID、表情名和表情 URL

#### Scenario: 表情广播保持房间隔离
- **GIVEN** `GameA` 和 `GameB` 是不同房间
- **WHEN** `GameA` 中的参与者发送表情消息
- **THEN** `GameB` 中的连接不会收到该表情消息

#### Scenario: 未校验连接不能发送表情
- **WHEN** 未完成房间校验的连接尝试发送表情消息
- **THEN** 服务端拒绝请求并返回可理解的错误信息

### Requirement: 表情发送必须由服务端校验清单
系统 MUST 以服务端当前表情清单作为表情发送的可信来源。客户端 MUST 只提交表情 ID；服务端 MUST 根据表情 ID 解析表情名和 URL。

#### Scenario: 客户端提交有效表情 ID
- **GIVEN** 表情清单中存在 `default/smile.png`
- **WHEN** 客户端发送表情 ID `default/smile.png`
- **THEN** 服务端接受该请求
- **AND** 广播消息中的表情 URL 由服务端清单解析得到

#### Scenario: 客户端提交不存在的表情 ID
- **WHEN** 客户端发送不存在于当前清单的表情 ID
- **THEN** 服务端拒绝请求
- **AND** 不广播任何表情消息

#### Scenario: 客户端不能指定任意表情 URL
- **WHEN** 客户端发送表情消息并尝试附带自定义 URL
- **THEN** 服务端忽略或拒绝客户端提供的 URL
- **AND** 广播消息不会包含客户端伪造的 URL

### Requirement: 表情消息必须参与聊天历史同步
系统 MUST 将成功广播的表情消息写入现有有界聊天历史。新连接或重连客户端 MUST 能在聊天历史中收到表情消息并按时间顺序展示。

#### Scenario: 新连接收到历史表情消息
- **GIVEN** 房间历史中已有文本消息和表情消息
- **WHEN** 玩家或观战者成功加入该房间
- **THEN** 客户端收到包含表情消息的最近聊天历史
- **AND** 历史消息按发送时间顺序展示

#### Scenario: 表情消息历史保留结构化字段
- **GIVEN** 房间历史中保存了一条表情消息
- **WHEN** 服务端下发聊天历史
- **THEN** 该历史项保留消息类型、表情 ID、表情名和表情 URL

### Requirement: 表情消息必须遵守聊天限流
系统 MUST 将表情消息纳入现有聊天发送频率限制，防止通过表情刷屏影响对战通信。

#### Scenario: 高频发送表情触发限流
- **WHEN** 同一参与者在短时间内连续发送超过阈值的表情消息
- **THEN** 超额请求被拒绝
- **AND** 服务端返回“发送过于频繁”类错误

#### Scenario: 文本和表情共享限流窗口
- **WHEN** 同一参与者在短时间内混合发送文本消息和表情消息并超过阈值
- **THEN** 超额请求被拒绝
- **AND** 限流不会因消息类型不同而绕过

### Requirement: 聊天界面必须提供分组表情选择器
客户端 MUST 在对战聊天界面提供表情入口，并按服务端返回的表情分组展示表情。客户端 MUST 在点击表情后立即发送表情消息。

#### Scenario: 打开表情面板显示分组
- **GIVEN** 表情清单包含多个分组
- **WHEN** 用户在 `game-chat-content` 中打开表情面板
- **THEN** 客户端显示分组 tab
- **AND** 默认展示第一个非空分组的表情网格

#### Scenario: 切换表情分组
- **GIVEN** 表情面板已打开且存在多个分组
- **WHEN** 用户选择另一个分组 tab
- **THEN** 表情网格切换为该分组下的表情项

#### Scenario: 点击表情立即发送
- **GIVEN** 表情面板已打开
- **WHEN** 用户点击一个表情项
- **THEN** 客户端发送该表情 ID
- **AND** 用户不需要再点击文本发送按钮

### Requirement: 表情选择器必须处理加载和空状态
客户端 MUST 在表情清单加载中、加载失败或清单为空时显示稳定状态，并 MUST NOT 破坏文本聊天输入。

#### Scenario: 表情清单加载失败
- **WHEN** 用户打开表情面板但表情清单请求失败
- **THEN** 客户端在表情面板内显示加载失败状态
- **AND** 文本聊天输入和发送仍可继续使用

#### Scenario: 表情清单为空
- **GIVEN** 服务端返回的表情清单没有可用表情
- **WHEN** 用户打开表情面板
- **THEN** 客户端显示“暂无表情”类空状态
- **AND** 不显示不可点击的伪表情项

#### Scenario: 关闭表情面板保留文本草稿
- **GIVEN** 用户已在聊天输入框中输入文本草稿
- **WHEN** 用户打开并关闭表情面板
- **THEN** 输入框中的文本草稿保持不变

### Requirement: 表情消息必须安全渲染并提供失败回退
客户端 MUST 根据消息类型区分文本消息和表情消息。表情消息 MUST 使用服务端广播的受信任 URL 渲染图片，并在图片加载失败时显示固定尺寸占位。

#### Scenario: 聊天列表展示表情消息
- **WHEN** 客户端收到表情消息
- **THEN** 聊天列表显示对应表情图片
- **AND** 表情图片带有可访问的替代文本

#### Scenario: 表情图片加载失败
- **WHEN** 表情消息中的图片 URL 加载失败
- **THEN** 客户端显示固定尺寸的失败占位
- **AND** 聊天消息行不会塌陷或遮挡其他消息

#### Scenario: 文本消息仍以安全文本渲染
- **WHEN** 客户端收到包含 HTML 片段的文本聊天消息
- **THEN** 客户端只按文本显示该内容
- **AND** 不执行任何 HTML 或脚本

### Requirement: 表情弹幕必须遵守现有聊天弹幕生命周期
客户端 MUST 能在实时表情消息到达时播放一次对战顶部弹幕，并 MUST 在离开对战页面后清理表情弹幕队列和 DOM。

#### Scenario: 表情消息触发顶部弹幕
- **WHEN** 客户端在对战页面收到实时表情消息
- **THEN** 客户端在顶部弹幕区域播放一次表情展示
- **AND** 弹幕结束后自动移除

#### Scenario: 离开对战页面后不播放表情弹幕
- **WHEN** 用户离开对战页面
- **THEN** 客户端不会继续播放表情弹幕
- **AND** 已排队但未播放的表情弹幕被清理

### Requirement: 表情图片加载不得依赖 SignalR 二进制传输
系统 MUST 通过静态资源 URL 加载表情图片。SignalR 消息和表情清单 API MUST 只传输表情元数据。

#### Scenario: 发送表情不传输图片二进制
- **WHEN** 用户发送表情消息
- **THEN** SignalR 请求和广播只包含表情元数据
- **AND** 不包含图片二进制或 base64 内容

#### Scenario: 浏览器通过静态 URL 加载表情图片
- **WHEN** 客户端渲染表情消息或表情网格
- **THEN** 浏览器通过表情 URL 请求静态图片资源
- **AND** 图片资源可使用浏览器缓存机制
