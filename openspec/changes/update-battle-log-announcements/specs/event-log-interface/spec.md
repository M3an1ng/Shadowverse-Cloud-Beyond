## MODIFIED Requirements
### Requirement: 统一事件公告接口
事件日志输出 MUST 依赖统一接口提供的公告文本；仅实现该接口的事件可被广播到前端日志。接口需支持基于事件实例生成可读公告，禁止在管线中使用手写 switch 映射。公告文本 MUST 以中文、用户友好的形式输出，并标记需要突出显示的可变量（如来源/目标/数值），以便前端渲染强调样式。公告文本中的可变量 MUST 使用统一标记语法 `[[...]]` 包裹，前端据此高亮。

公告文本风格要求：
- 叙述式中文短句，避免命令式动词与 key=value 结构
- 使用全角标点，数值后带量词/单位（如“点伤害/点治疗”）
- 变量顺序：来源 → 目标 → 数值（缺省来源时省略来源片段）
- 所有 ID 类字段 MUST 解析为可读名称：
  - 卡牌 ID → 卡牌名称，名称使用『』包裹
  - 主战者 → 『我方主战者』或『敌方主战者』
  - 玩家 ID → 玩家名称，并自动区分“我方/敌方”（如“我方玩家/敌方玩家”或“我方/敌方 + 名称”）
- Battle Log 每条 MUST 使用回合号前缀，而非时间戳（格式：`[Turn N] ...`）

示例（DamageEvent）：
- 有来源：`[Turn 1] 『哥布林』对『我方主战者』造成 [[数值]]点伤害。`
- 无来源：`[Turn 1] 『敌方主战者』受到 [[数值]]点伤害。`

示例（TurnStartEvent）：
- `\[Turn 1] 我方回合开始。`
- `\[Turn 1] 敌方回合开始。`

#### Scenario: 公告事件生成日志文本
- **WHEN** 一个实现公告接口的事件被广播
- **THEN** 系统调用其公告方法生成中文可读文本（变量以 `[[...]]` 标记），并发送到前端日志 UI，前端可突出显示关键变量

#### Scenario: 非公告事件不进入日志
- **WHEN** 事件未实现公告接口（如 HandPlayabilityUpdateDto）
- **THEN** 前端日志不显示该事件
