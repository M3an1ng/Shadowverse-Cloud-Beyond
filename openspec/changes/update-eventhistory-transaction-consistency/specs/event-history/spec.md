## MODIFIED Requirements

### Requirement: Event history MUST be transaction-consistent for trigger evaluation
The system SHALL persist processed events during transaction execution so ability evaluation in later phases of the same transaction can observe newly committed events.

#### Scenario: Committable event visibility before After phase
- **GIVEN** a committable event has successfully executed `Commit`
- **WHEN** the transaction evaluates `After` timing triggers for that event and nested events generated by the commit
- **THEN** DSL reads from `context.eventHistory.events` MUST include that committed event

#### Scenario: Non-committable event visibility before After phase
- **GIVEN** a non-committable event has completed `Before/On` handling
- **WHEN** the transaction evaluates `After` timing triggers
- **THEN** DSL reads from `context.eventHistory.events` MUST include that event

### Requirement: Event history reader MUST expose latest persisted history
The system SHALL not return stale cached snapshots from `EventHistoryReader` across repeated reads.

#### Scenario: Re-read after new history write
- **GIVEN** an `EventHistoryReader` has already returned events for a game
- **WHEN** additional events are persisted to the same game history
- **THEN** the next `EventHistoryReader.Events` read MUST include newly persisted events
